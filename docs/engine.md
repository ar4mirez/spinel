# Engine

The VM that runs Ruby. Every choice below is either a **decision** (settled with the owner, listed in [design.md](design.md)) or a **default** (a reasonable starting point that a slice may replace if ruby/spec or a benchmark says so). Defaults are marked.

**Language version.** Spinel implements one Ruby language version at a time, the latest stable release (4.0 at launch), and `RUBY_VERSION` reports it. ruby/spec is checked out at the matching branch so `ruby_version_is` guards select the right specs. See cli.md for the full identity table.

## Pipeline

```
source ──Prism──▶ spinel_ast ──resolve──▶ bytecode ──▶ interpreter (+ inline caches)
                              (locals,                       │
                               scopes,                       ▼ phase 6
                               constants)              Cranelift JIT
```

- **Parse.** `spinel-parse` lowers Prism's tree into `spinel_ast`. Error-tolerant: syntax errors become nodes with diagnostics, so tooling can still format or lint a broken file.
- **Resolve.** Ruby needs to know which bare identifiers are locals versus method calls, which slot each local gets, and which variables a block captures. The first is decided in `spinel-parse`, because Prism decides it and the lowering keeps the answer as `VarRef::Local` versus a `Call` with `variable_call`. The second is done by the compiler as it walks, since a scope's slot map is exactly what the compiler is already building. Landed that way in [#10](https://github.com/ar4mirez/spinel/issues/10): a separate pass had nothing left to do that the walk was not doing anyway. Capture analysis has no home yet and gets one with blocks, in [#11](https://github.com/ar4mirez/spinel/issues/11) — that is the pass this line originally described, and the only part of it that is a real pass.
- **Compile.** One bytecode function per method, block, or top-level script. Blocks compile to their own function with a pointer to the enclosing frame's environment. Bytecode is immutable and position-independent (symbols by name, relinked on load), so it can be cached on disk and shared between Ractors.
- **Execute.** A non-recursive interpreter loop. A Ruby-to-Ruby call pushes a frame and continues the same loop; it does not recurse on the Rust stack. This matters for fibers and for deep recursion limits that match Ruby's.

### Bytecode

Landed in [#10](https://github.com/ar4mirez/spinel/issues/10). An `Iseq` is a
`Vec<Insn>` — a Rust enum, not a packed byte buffer, because the decode step a
buffer buys is the `match` an enum already does and `Insn` is `Copy` and 16
bytes either way. The on-disk form phase 3 caches is therefore a *serialisation*
of the enum rather than the enum's own bytes.

Three rules make an `Iseq` position-independent, which is what lets it be cached
on disk and shared between Ractors:

- **Jumps are relative**, counted from the instruction after the jump, so an
  `Iseq` never needs relocating.
- **Symbols are names.** The pool holds `Box<str>` and instructions index it;
  `Iseq::link` interns the pool against the process table. Two processes agree
  about symbols without agreeing about the order they first saw them in.
- **Literals are descriptions**, never `Value`s, because a `Value` can be a
  pointer into one heap. Materialising is per heap, which is also what makes a
  string literal a fresh object per evaluation, as Ruby requires.

Arithmetic and comparison are instructions rather than sends — `opt_plus` and
friends, as YARV has them: a fast path for a pair of numbers with a real send
behind it for any other operand. The operators are in the method table too:
`Integer#+`, `Float#<` and the rest are primitives over the same function the
instruction calls, so `2.send(:+, 1)`, `respond_to?(:+)` and `inject(:+)` agree
with `2 + 1`, and `Numeric`'s coercing operator is their `super`. The
instruction keeps its fast path only while the name still resolves to that
primitive, public: the class table records the bodies it installed and
re-reads them after any definition, so `class Integer; def +(o) = 42; end` is
heard at the next `1 + 1` (#239, PRD 0056), and so is `private :+` (#751).
`==` is one of them, with `===` the same method
as CRuby's `int_equal` and `flo_eq` are, and a number compared with an object
that is not one asks the object, `obj == 1` (#345, #349); `!=` follows a
redefined `==`. Code in `core/*.rb` is exempt, as C is in CRuby.
A program's change to one of the methods CRuby optimises — its measured list,
wider than these operators — is what `Warning[:performance]` reports, once per
body the core library installed (#320).
Integer overflow promotes to a bignum.

**Superinstructions** ([#746](https://github.com/ar4mirez/spinel/issues/746),
[#750](https://github.com/ar4mirez/spinel/issues/750)). Once a body is
compiled, `bytecode::fuse` writes a superinstruction over the first instruction
of each run of instructions that has one. The runs were chosen by counting,
over the yjit-bench programs and `bench/interp_loops.rb`, which instructions
run one after another in the same frame:

| superinstruction | stands for | e.g. |
|---|---|---|
| `GetLocalPushIntBinOp { slot, int, op }` | `GetLocal(slot, 0); PushInt(int); BinOp(op)` | `n < 2`, `i += 1` |
| `GetLocalGetLocalBinOp { left, right, op }` | `GetLocal(left, 0); GetLocal(right, 0); BinOp(op)` | `i < n`, `dx * dx` |
| `GetLocalGetIvarBinOp { slot, site, op }` | `GetLocal(slot, 0); GetIvar(_, site); BinOp(op)` | `sum += @v` |
| `GetLocalBinOp { slot, op }` | `GetLocal(slot, 0); BinOp(op)`, the left operand already on the stack | `dx * mag` |
| `PushSelfGetLocal { slot }` | `PushSelf; GetLocal(slot, 0)` | `check(tree)` |

A superinstruction's name is the instructions it stands for, in order, and its
fields are theirs. It replaces only the first of them. The rest of the run
stays where the compiler wrote it, so nothing moves. The jumps, the catch
table, the line table and the inline-cache sites are untouched, and a jump
into the middle of a run lands on a real instruction. A run can start inside
another: in `GetLocal a; GetLocal b; PushInt 1; BinOp(+)` the first
`GetLocal` heads nothing, and the second heads a `GetLocalPushIntBinOp`. In
`GetLocal a; GetLocal b; BinOp(*)`, the first heads a `GetLocalGetLocalBinOp`
and the second a `GetLocalBinOp`, which is reached only by a jump into the run
or by a decline of the first.

The light loops answer a superinstruction in one dispatch when every
instruction of its run would have run light, as it would have answered there:

- a local of a frame whose locals are on its stack;
- a fixnum, or in `more_stretch` a flonum, under an operator the program has
  not redefined, with an immediate answer;
- an instance-variable read that its site's cache answers.

The `SetLocal` or conditional jump after the run is run with it, as after a
`BinOp`. A `GetLocalPushIntBinOp` is answered by one copy of its run for each
operator, with the operator a constant in it: its bit of the operator mask is
a constant test, and its arithmetic follows the one jump on the operator,
rather than a test of a shifted bit and then a second jump inside
`fixnum_binop` (#746). `fuse` writes a `GetLocalPushIntBinOp` only for a
literal that is a fixnum, so each copy makes its operand without asking whether
it is in range; a literal past the range is left as the three instructions it
would stand for. The same copies for `BinOp` itself measured worse, so
it keeps one test of the mask and `fixnum_binop`'s own jump. Anything else
is a *decline*. The superinstruction then runs only its
first instruction (`Insn::head`), and the loop goes on at the next `pc`, where
the rest of the run executes as it always did. So every send, error,
backtrace line and allocation is the unfused program's. `run`'s own step
always declines: it runs the first instruction of every stretch, and the
fused path in its code cost each instruction it dispatches.

The operators fused are those the light loop answers. `%` is never fused.
`*` and `/` are fused with a local or an instance variable, for flonums, but
not with an integer literal, since two fixnums never answer light. A
`PushSelfGetLocal` is not written where its `GetLocal` heads a longer run: fib's
`fib(n - 1)` pushes `self` and then runs `n - 1` as one instruction.

Each superinstruction is code in every light loop, and an arm that some loops
never run costs them registers, as the Float arms did (#750). Each one was
kept only if it paid in instructions retired across the yjit-bench programs and
`bench/*.rb`. The roadmap lists the forms measured and not kept, and the
candidates not built, with their numbers.

## Values

Landed in [#6](https://github.com/ar4mirez/spinel/issues/6). A 64-bit tagged word,
CRuby's proven scheme:

| low bits | the rest of the word | kind |
|---|---|---|
| `1` | 63-bit signed integer | fixnum |
| `10` | double, rotated left by three | flonum |
| `0100` | ordinal | `nil`, `false`, `true`, `undef` |
| `1100` | symbol id | static symbol |
| `000` | 8-byte-aligned pointer | heap object |

The zero word is deliberately not a `Value`. `Option<Value>` is therefore one word as
well, and a zeroed slot is a detectable bug rather than a plausible object.

Flonums cover the doubles whose top three exponent bits are `011` or `100`: magnitudes
between roughly 1.7e-77 and 1.8e77, which is every float a normal program holds. NaN,
the infinities, `-0.0`, and the extremes allocate instead. Excluding those three is also
what makes bitwise equality on `Value` exactly Ruby's `equal?`, which the interpreter,
the method cache, and the GC all rely on.

`Integer` promotes to a heap bignum past ±2^62. Bignum arithmetic is a primitive over a
pure-Rust bigint crate.

## Heap and GC

**Decision:** one `Heap` per Ractor. `&mut Heap` is passed explicitly through the VM; there is no global.

**Default GC:** precise, non-moving mark-sweep with size-class free lists and a large-object space. Precise because the compiler knows every root: the VM stack, frames, the current exception, per-heap tables, and Rust-side handles. Rust code holds `Value`s only inside a `HandleScope`, so a GC in the middle of a primitive cannot lose them. Non-moving first because it is the simplest correct thing. Because there is no C API pinning objects, a moving generational collector is a contained upgrade later; `spinel-ext` uses handles from day one so extensions survive that upgrade.

Landed in [#7](https://github.com/ar4mirez/spinel/issues/7). The object header is 16 bytes:

| offset | field | notes |
|---|---|---|
| 0 | class pointer | `Option<Value>`; also the free-list link while the cell is free |
| 8 | `len` | `Value` slots, or bytes |
| 12 | flags | mark bit; frozen (#8); ractor-shareable, for a `Proc` made shareable (#118), and alone, unfrozen, for `ENV` (#865); side-table ivars; chilled, for a String literal or `Symbol#to_s` that warns when first mutated (#263); keywords, for a Hash `ruby2_keywords` collected (#200) |
| 13 | payload kind | slots or bytes — whether the collector descends |
| 14 | shape id | which instance variables the object holds, and where |

Instance variables live in a slots array indexed by the shape; the shape tree is per heap. Landed in [#151](https://github.com/ar4mirez/spinel/issues/151).

Cells come from 64 KiB blocks, one size class per block: 32, 64, 128, 256, and 512 bytes, holding 2, 6, 14, 30, and 62 slots. Anything larger gets its own allocation in the large-object list. Sweeping rebuilds every free list from the unmarked cells, so a dead object and a cell that has never been used take the same path; blocks are zeroed on arrival so that an unused cell reads as unmarked rather than as uninitialised memory.

A collection runs inside an allocation, when bytes since the last one cross a threshold — 1 MiB, then twice the live bytes, floored at 1 MiB — or when a caller asks. There is no collector thread and no interior mutability, so every collection point is a `&mut Heap`, which is what makes "a GC in the middle of a primitive" something the compiler can see.

Ruby reaches the collector through `core/gc.rb` ([#36](https://github.com/ar4mirez/spinel/issues/36)). `GC.disable` is a flag that allocation checks, and `GC.stress` makes every allocation collect. `GC.start` does not collect inside its own native: it sets a request, and the interpreter loop collects at the next call or return, after letting go of the handles it took for instructions that have finished. Collecting in the native would keep alive everything those stale handles name, and `GC.start` is the one collection a program expects to free what it just dropped.

Weak maps and finalizers are side tables keyed by an object's address, like side-table instance variables, so neither needs a header bit. A `WeakMap` or `WeakKeyMap` keeps its entries in the heap, keyed by the map object, and `mark` never traces them. Once the strong roots have drained, a second pass marks each `WeakKeyMap` value whose key survived, repeated until a pass marks nothing, since one map's value can be another's key. That makes a `WeakKeyMap` entry an ephemeron. Every surviving map then drops the entries whose referents did not survive, and a map's table goes with the map before `sweep`. The fstring table, the one frozen literals are interned in, is weak the same way for the Strings `String#-@` interns (#384): its pass drops each that did not survive. A literal's own entry is a root, as CRuby's iseq holds it, and a `-@` entry a frozen literal then answers becomes one. A finalizer's callables are roots and its object is not. When a collection finds the object dead, the callables move to a queue with the object's id before `sweep` frees the cell. The loop drains that queue at a call or a return, by pushing a call to `Kernel.__run_finalizers__`, so a finalizer gets the id and never the object and cannot resurrect it. Whatever is still registered when the program ends runs after the `at_exit` blocks. A `dup` or `clone` is registered with the original's callables, as CRuby's `init_copy` copies them, so each runs once more, for the copy. `objspace`'s allocation tracing (#690) is a third such table: while tracing is on, `allocate` notes the address of each object with a class, and the interpreter loop files those addresses under the frame and line the instruction that allocated them ran at. The allocator cannot see the frames, and the loop can. Each loop, every thread's included, looks at whether tracing is on at a call, a return or a turn check, where it already stops to look for a `GC.start`, and from then on raises its budget limit to the maximum so the compare every instruction already makes sends each one through a cold stamping step. With tracing off the loop pays nothing per instruction and the allocator one flag test.

`HandleScope` is the discipline, and it is enforced rather than documented: `Heap` has no method that allocates. `HandleScope::alloc` returns a `Handle` — an index into the heap's root stack — and never a bare pointer, so an object the collector cannot see is a program that does not compile. A scope pops its own handles on drop, and a nested scope's handle cannot escape into its parent because `Handle` is covariant in the scope's lifetime. Today the root set is exactly that stack; the VM stack, frames, the current exception, and the per-heap tables each plug into the same mark phase as their slice lands.

## Classes and ancestor chains

Landed in [#8](https://github.com/ar4mirez/spinel/issues/8). Every class and module owns a **run** of the ancestor chain: the modules prepended to it, then the class itself, then the modules included in it. A class's ancestry is its own run followed by its superclass's, so `include` on a superclass is visible to every subclass with nothing propagated, and `ancestors` is a walk.

The run is maintained by `include` and `prepend` rather than recomputed from a list of mixins, because the order depends on the state of the chain at the moment of each call: `include M; include B; include A` where `A` also includes `M` gives `[C, A, B, M]`, and no replay of `[M, B, A]` against `A`'s final contents produces that. Ruby 3.0's [Feature #9573](https://bugs.ruby-lang.org/issues/9573) — a module gaining an include reaches back into everything that already mixed it in — is a flat list of includers per module, patched at each includer's own copy of the module.

These rules are CRuby's, and they were measured rather than read: `crates/spinel-vm/tests/ancestors.txt` is 42 hierarchies with the ancestors a real Ruby computes for them, `scripts/ancestors-oracle.rb` is what re-measures it in CI, and `tests/ancestors.rs` is what holds Spinel to it.

Singleton classes are allocated on first ask, with one exception: the `class` keyword builds a class's metaclass as it defines it, because `class B < A` with a `def self.m` on `A` reaches `m` through `#<Class:B> < #<Class:A>` and a `B` still pointing at `Class` would miss it. That is CRuby's `rb_define_class`, and `HandleScope::define_class` stays lazy for everything else — except that making a class's metaclass also makes one for each subclass that already exists without one, so a class bootstrap defined before its superclass gained class methods still reaches them (#29). A class's singleton inherits from its superclass's, `BasicObject`'s inherits from `Class`, and a module's inherits from `Module` — the twist that puts `Class`, `Module`, `Object`, `Kernel`, and `BasicObject` at the end of every metaclass's ancestors. An ordinary object's singleton *becomes* its class, as in Ruby, so the header write is the whole mechanism.

Method tables are Rust hash maps hanging off the class table, not object slots, so the class table is a root source in `Heap::mark`: it holds every method body, every constant, and every class variable, which the main Ractor's heap traces, while each heap traces its own object for each class (#117, "Ractors and threads").

`undef` writes a **tombstone** rather than removing an entry: a body of `Value::UNDEF` that the chain walk finds and then reports as nothing found. That is what separates it from `remove_method`, which removes the entry and lets the superclass's method through — `Class.new(sup) { undef a }.new.a` is a `NoMethodError` where the same class with `remove_method :a` answers `sup`'s. `respond_to?`, `method_defined?` and the `NoMethodError` all fall out of the one representation, and a later `def` overwrites it. `alias` copies the entry it finds *now*, visibility included, so redefining the original afterwards does not move the alias. The copy remembers its **origin** — the class and name the body was defined under — as does the copy `public :m` makes of an inherited `m` (CRuby's `ZSUPER` entry), so `super` in it goes on from there under that name rather than finding the copy again (#27). The core library's own aliases record none: each stands for a C method CRuby defines twice, and answers `original_name` with its own name.

Each entry also carries a **representation**: the built-in whose shape its instances have, inherited from the superclass when the class is created ([#199](https://github.com/ar4mirez/spinel/issues/199)). `Builtin::ALL` is indexed by class id, so asking it about a user-defined class answers `None` however built-in that class's ancestry is — which gave `class MyString < String` the plain-object shape. The representation is the question `allocate` and every primitive asks about a receiver instead, so `MyString.new("b")` allocates a string, answers `MyString`, and is read by `String#size`; and a class whose representation has none that can be built — `Proc` — still refuses, subclass included, rather than handing back a plain object wearing its class. Routing such a class to its built-in ancestor's *class object* was measured instead and costs 45 examples, because `MyString.new.class` then answers `String`. A `Regexp` can be allocated since [#33](https://github.com/ar4mirez/spinel/issues/33): a pattern with no table entry, every reader of which but `inspect` raises `TypeError` until `Regexp#initialize` compiles into it.

## Constants and lexical scope

Landed in [#13](https://github.com/ar4mirez/spinel/issues/13). A constant belongs to exactly one module and lives in a hash map on that module's class-table entry, beside its methods and rooted by the same walk.

Lookup needs the chain of `class`/`module` bodies a reference was **written** inside, which is not the chain it **runs** inside:

```ruby
module A
  X = 1
  class B
    def m = X          # A::X, though B.ancestors never reaches A
  end
end
```

The compiler cannot supply that chain — it knows `B` is one level deeper, but `B` is a `ClassId` that does not exist until the body runs — so it is built at runtime, as CRuby's cref is. A `CrefId` indexes a per-heap arena of `(class, parent)` nodes. It is an arena index rather than a heap object because a cref is unreachable from Ruby, never outlives the modules it names, and is read on the hot path of every constant reference; the `ClassId`s in it are already rooted by the class table.

Three things carry one, because a reference resolves where it was written: a frame carries the scope that pushed it, a `Method` carries the scope its `def` appeared in, and a `Proc` carries the scope it was created in as a sixth slot.

A bare `X` searches the cref chain innermost-first (own tables only) **except its outermost node**, then the innermost scope's ancestors, then `Object` if that scope is a module. Skipping the outermost node is what makes an ancestor's constant beat a top-level one of the same name — the ancestor walk covers that node anyway, and covers it with its ancestors — and asking whether the scope is a *module* rather than whether its ancestors reached `Object` is what gives `BasicObject` and its subclasses an empty constant namespace. `A::X` is `A`'s own table and then the ancestor walk rooted at `A` — own table first, so a module prepended to `A` does not shadow `A`'s constant, as a prepend moves methods behind the module and not constants — with no lexical scope and no `Object` fallback; Ruby removed that fallback in 2.5, so `Sub::TOP` for a top-level `TOP` is a `NameError`. `::X` is the ancestor walk rooted at `Object`. `private_constant` marks a name in one module's own table, and hides it from the `A::X` walk alone.

These rules are documented nowhere and read wrong from `variable.c`, so like the ancestor chain they are measured rather than believed: `crates/spinel-vm/tests/eval.txt` holds them and `scripts/eval-oracle.rb` re-measures them in CI.

`defined?` reads the same tables and answers a table of Ruby's own strings. Where it *misses* it answers Ruby's `nil`, since `require` landed (#39) and a program can load what it needs — except in a heap marked partial, where a file meant to run did not finish: `spec/spinel/runner.rb` marks one whose fixture stopped part way, and there a miss is `Error::Unknowable`, because `nil` would pass a spec the VM had no right to.

## Shapes and inline caches

Instance variables use hidden-class shapes (V8, YJIT), landed in [#151](https://github.com/ar4mirez/spinel/issues/151). A shape is a path from a per-heap root: each edge adds one name at one index, so two objects built the same way meet at one node and carry the same `u16` in the header's reserved bytes, while `@a` then `@b` and `@b` then `@a` are two shapes. That divergence is the mechanism, not a wart — it is what makes an index constant for every object wearing a shape.

Where the values live is the same answer `Array` gives for its elements, for the same reason: a heap cell cannot grow, so an object that held its ivars directly could gain the fourth only by becoming a different cell, and Ruby would see `equal?` change. Slot 0 of an ivar-capable object points at a classless storage object that is *replaced* when it grows; the object's own address never moves, and the collector needs no new root because it already descends into slots.

A shape id of zero is not the root — it means the object holds no instance variables, and for an object whose payload is a representation of its own, that it has no slot for them either. Slot 0 of an `Array` is its elements and slot 0 of a `Proc` is its iseq, so `@x = 1` on an array cannot go where it goes on a plain object. It goes in a side table instead: the heap keeps the storage object for such an object by its address, a header flag says to look there, and from then on the object wears a shape like any other. The entry is traced from its object and dropped with it, which a collector that does not move makes a matter of one lookup in `mark` and one pass before `sweep`. Nothing pays for it but the objects that use it, and `Marshal` was the workload that asked (#37): a `_dump` String carries a Time’s zone as an instance variable.

Three fixed-slot schemes were deleted rather than left beside it: a class object carries its table id as the hidden `@__id__`, an exception's message and backtrace are `@__message__` and `@__backtrace__`, and a `Hash`'s association list, default and default-is-a-block are three ordinary ivars that `core/hash.rb` reads directly. Since #21 the core library's own ivars are spelled `@__name__`, and `instance_variables` leaves that spelling out — `{}.instance_variables` is `[]`, as in CRuby, which keeps the same state out of Ruby's sight. `attr_accessor` addresses a *name* for the same reason — which slot an ivar lands at is the shape's business, so a reader built on a fixed slot would be right for a class with one ivar and wrong for its second.

A method carries its visibility, landed with [#161](https://github.com/ar4mirez/spinel/issues/161). It sits on the `Method` the caches memoise rather than beside it, so a warm call site checks `public`/`private`/`protected` for free; the price is that `private :m` has to bump the class serial exactly as redefining `m` does, which `Classes::set_visibility` does. What a bare `private` sets for the `def`s below it is a different thing and lives on the *frame* — CRuby's `CREF_SCOPE_VISI` — because it belongs to one execution of one body: a block shares it, a method body resets it, and reopening a class starts public again. That field is a `ScopeDefault`, not a `Visibility`, because a bare `module_function` sets the same state to a fourth mode ([#211](https://github.com/ar4mirez/spinel/issues/211)): a body is in exactly one default, so `private` after `module_function` replaces it outright rather than combining with it. `Insn::DefineMethod` branches on the mode — `ModuleFunction` makes a public copy on the module's singleton *and* a private instance method — while everything else that reads the default, `attr_accessor` among them, takes only its visibility half, which is why `module_function; attr_accessor :x` makes a private reader and no singleton copy. All measured on ruby 4.0.6.

Method lookup uses a per-class method table plus a method cache, landed with [#8](https://github.com/ar4mirez/spinel/issues/8) and sharpened in [#9](https://github.com/ar4mirez/spinel/issues/9). The cache lives *in the class entry*, keyed by symbol, rather than in one table keyed by `(class, symbol)`: that is what makes eviction precise, because invalidating a class is emptying its own map and no key has to be scanned to find out whose it was. Misses are cached too, so a `method_missing` dispatch does not re-walk the chain per call.

Each class carries its own serial, bumped by anything that can change what a name resolves to *for that class*: a definition or removal here or in an ancestor, an `include`, a `prepend`, an `extend`, or a definition on a singleton class. A definition somewhere unrelated leaves it alone. Propagating it is a walk over two edges — `subclasses` for inheritance, the existing flat `includers` for mixins — from the class that changed, down to everything that has it in a chain. That set is exactly the set that could have cached an answer the change invalidates.

The cache is emptied rather than stamped and left, because a stale entry can name a body that `remove_method` just dropped, and the cache would be the only thing keeping it from the collector — a stamped cache is a GC bug, not just a stale answer.

The trade is measured in `bench/method_cache.rs`: precision costs a walk per definition, worst case every class in the heap when the definition is on `Object`, which shows up as roughly a quarter more time to load `core/*.rb`. It buys back a cached answer that survives an unrelated definition — 3.5x on a dispatch-while-defining workload, against a design where any definition evicted everything.

Call sites carry a monomorphic inline cache `(class, serial, target)`, landed in [#169](https://github.com/ar4mirez/spinel/issues/169), with the entry a second receiver class displaced kept behind it, plan and all, and swapped back in front when that class returns ([#751](https://github.com/ar4mirez/spinel/issues/751)); the site finds what is behind it by an index of its own, not a hash of its slot, since a site that sees two classes in turn swaps at nearly every call. Because bytecode is shared across Ractors, inline caches do not live in the bytecode; each heap owns a side table indexed by call-site id. A call-site id is the `Iseq`'s run in that table plus the `Insn::Send` operand, and the run is found once per frame push, beside `Iseq::link` and for the same reason: the one hash probe the design needs belongs on frame entry, not on every send. Class serials live on the shared class entry, so every heap sees an invalidation; a heap reads one only while it holds the class lock, which no write overlaps ("Ractors and threads"). These are day-one features because retrofitting them into a VM that assumed direct table lookups is painful.

Beside each entry the table keeps a *plan*: how a call from that site binds the method the entry holds, worked out the first time the entry answers a call and forgotten when it is refilled ([#748](https://github.com/ar4mirez/spinel/issues/748)). It is CRuby's `vm_callee_setup_arg` deciding once per call site that a call can take its fast path, with the keyword half of it — which declared keyword each passed one binds, which optional parameters the site leaves out — decided once rather than per call. It needs no guard of its own: the entry's class and serial already fix the method, so its body, and the site is fixed by the slot. A plan also holds what a frame push would otherwise look up — the callee's own run of entries, so the hash probe above happens once per site rather than per push — and the receiver class's object, which a receiver whose header names it is an instance of: a class object is never collected, since the class table roots every one, so the compare is the guard short of the class id (`Class` itself, where `class_of` may answer a singleton class's new singleton instead, never gets a plan: the fast path finds a receiver's class only when it can without allocating, and declines a receiver whose header names `Class`). A plan that says no says it until the entry is refilled, so a send from such a site — a native's, for one — goes straight to `dispatch` without trying the fast path's lookups first. A `yield` site resolves no method and its entry is never filled, so its slot holds the block body it last yielded to and what that body's parameters allow, guarded by the body, a definition id that names one `Iseq` for the life of the heap.

The thing an inline cache has to beat is not the chain walk but the *cached* lookup, because the per-class cache above already turns every chain depth into one hash probe. It does: two integer compares against a `Vec` entry, measured at 1ns against the probe's 8ns, and about 10% off a send-heavy loop end to end.

An instance-variable read has an inline cache too, landed in [#747](https://github.com/ar4mirez/spinel/issues/747): `Insn::GetIvar` carries a site number, and the site's entry is the shape the receiver last wore there and the index that shape gives the name. Such an entry needs no serial and is never invalidated, because a shape is a fixed path of names: the index a shape gives a name never changes, and a site reads one name. The entries sit in the same per-heap runs as the call sites, after them, so one base per frame serves both; an empty entry holds `ShapeId::NONE`, which no object with instance variables wears. A hit is the receiver's shape compared and a slot read, with no handle taken. A miss — another shape, storage in the side table, no such variable — is the full read, which fills the entry when it found the name in the object's own storage.

A write has one too, landed in [#750](https://github.com/ar4mirez/spinel/issues/750): `Insn::SetIvar` carries a site from the same numbering, and a hit is an overwrite of a name the receiver already holds, in the shape the site saw last, of an object neither frozen nor chilled — no transition, no storage that grows, so nothing that can collect. A first write, which moves the object to a new shape, a frozen object's `FrozenError` and side-table storage are the full write, after which the entry holds where the name now is. An `attr_reader` called from a site whose plan names the primitive (below) uses the site's own slot of the same table, one no `GetIvar` uses, as its cache; unlike a `GetIvar` entry it is emptied when the site's entry is refilled, since the new method may read another name from the same shape (an `alias_method` over a reader, say).

A constant read has one as well ([#750](https://github.com/ar4mirez/spinel/issues/750)): `Insn::GetConst` carries a site, after the ivar sites in the same run, whose entry is the value found, the scope and module it was read from, and the class table's *constant epoch* at the time. The epoch is one counter for the whole table, moved by everything that can change what any read answers — a constant assigned, removed or copied with its module, made private, public or deprecated, a mixin spliced into a chain, a superclass given, a constant-only scope pushed — so an entry is believed only while nothing anywhere has moved it. That is CRuby's `ruby_vm_constant_cache_invalidations` rather than its per-name invalidation, and it is the opposite trade from the method cache's precision above: a program that defines constants as it runs is rare, one that reads them in a loop is not, and the counter is one compare. A stale entry's value may be one the collector has since freed, but it is never read — the epoch has moved — and a current entry's value is still in the table it came from, which roots it. A name with an autoload waiting is never answered from the cache, since registering one moves no epoch, and a deprecated constant is never cached, so it warns at every read as it did before. A lexical or top-level read that hits is a light instruction (below), since its module follows from the scope.

Unlike the per-class cache, inline-cache entries are left to go stale rather than emptied. The reason that cache is emptied does not reach here: a `Method` is an owner id, a cref id, a fixnum definition id, and a visibility — two indices into per-heap arenas that only grow, an enum, and a body the collector never traces — so a stale entry roots nothing, and the guard can be lazy. Only hits are stored; a miss falls through to the per-class cache, which memoises the `None` itself.

## Calling convention

Ruby's full argument protocol from the start, because ruby/spec's `language/` directory exercises all of it and everything else depends on it: required, optional, splat, post-required, keyword, keyword splat, `**nil`, block argument, block pass, anonymous `*`/`**`/`&` forwarding, `...`. Arity errors match Ruby's messages exactly; the spec checks the text.

Landed in [#11](https://github.com/ar4mirez/spinel/issues/11), less the parts that need a class the VM does not have yet: `**kwrest` collects into a `Hash` and there is no `Hash`, and `&`/`...` forwarding waits with it. One `bind` fills a frame's parameter slots from a call's arguments, and the caller never inspects the callee's parameters — which is what makes an ordinary call, `send`, `yield`, and `Proc#call` the same code path with a different receiver. The one exception is the fast path below, which looks at them once per call site, through the site's plan, and only to decide that `bind` would write each argument to a slot and nothing else.

A method or lambda and a block differ in exactly two places, and both are the binder's: a lambda checks arity and raises `ArgumentError`, and a block pads with `nil`, drops extras, and spreads a single `Array` across its parameters when it has room for more than one value. `{ |a| }` and `{ |*a| }` take the array whole; `{ |a, b| }` and `{ |a,| }` spread it.

A call site is a table entry rather than an instruction operand: `Insn::Send(u32)` indexes `Iseq::call_sites`, which carries the name, the positional count, the keyword names, and what block the call passes. That is where the inline caches above go, since they are per heap and bytecode is not.

`for` is compiled as `each` with a block and is *not* a block, because `for` opens no Ruby scope: its variable and its body's locals belong to the scope around the loop and outlive it ([#212](https://github.com/ar4mirez/spinel/issues/212)). The block's environment is marked synthetic, and Prism's depths — which count Ruby scopes — are translated into run-time environment depths before a depth becomes a slot, skipping the environments Ruby cannot see. That translation is what lets a block written inside a `for` body reach the locals around the loop, and a `for` nested inside *that* block reach them one environment further out than Prism counted; `for_spec.rb` asserts on exactly that shape. The block holds one local of its own, the element, under a name Ruby cannot spell.

`ruby2_keywords`, the bridge Ruby 3 left for Ruby 2's convention, is two reads of one flag ([#200](https://github.com/ar4mirez/spinel/issues/200)). Marking a method or a `Proc` records its `Iseq` in the heap's `Definitions`, so an alias and every proc of one block literal share the mark, as they share CRuby's iseq flag. `bind` asks only when a call passes keywords to a body with a rest parameter, and then sets a header bit on the Hash those keywords become. `pop_call` reads the bit after expanding a call's splats: a flagged final Hash, on a site that writes no keywords of its own, leaves the positional arguments and becomes the call's keywords. A bit rather than an ivar because `inspect` must not show it and a copy must not carry it — measured, CRuby's `dup` leaves the flag behind.

Optional and keyword defaults are code at the top of the body rather than something the binder evaluates. The binder writes an undef marker into the slots a call left out, and each default is guarded by a `JumpUnlessUndef`. That handles a default that calls a method, and it handles keywords — which are independent rather than a fall-through chain, so a per-parameter entry offset would not.

## Frames, blocks, exceptions, fibers

- Frames hold locals, an environment pointer for captured variables (environments are heap-allocated only when a block captures them; default: a `captured` bit from the resolve pass decides), the receiver, the method entry, and a catch table.
- As landed in #11, a frame is a value in a `Vec` that the loop pushes and pops, so a Ruby-to-Ruby call never grows the Rust stack. A captured scope's locals live in a heap environment whose first slot links to the enclosing one, and `GetLocal` carries a depth that walks it. The environment is a plain slots object, so the collector traces a captured local with no code that knows what an environment is.
- A body with no enclosing scope — a method's, or a required file's top level — does not start with one ([#746](https://github.com/ar4mirez/spinel/issues/746)). Its locals live on the operand stack below its operands, as CRuby's do, and move to a heap environment the first time something captures them: a block literal, `binding`, an `eval` string. From then on the frame reads them there too, so a block and its method see one variable. That is the run-time half of the escape analysis above, deciding at the capture instead of in a resolve pass: a body that never captures never allocates, and one that captures pays for one environment. A block's body entered by `yield` or as a `define_method` body starts the same way ([#748](https://github.com/ar4mirez/spinel/issues/748)): its frame's `env` holds the environment of the scope it was written in while its own locals are on the stack, a local `depth` scopes out is read at `depth - 1` from there, and the environment a capture makes links to it, as one made at entry would have. An `eval` string's body, and a block whose first frame is built beside a stack it will not run on — a new thread's or fiber's — still start with a heap environment linked to the enclosing one.
- A call to a Ruby method from a site with no block, whose inline cache already holds the method, and whose plan says `bind` would only write arguments to slots — required and optional positionals and keywords, with nothing to collect into a rest, a `**kw` or a `&blk`, no keyword packed into a Hash, every keyword the site writes declared and every required one written — is pushed without building the call's argument list ([#748](https://github.com/ar4mirez/spinel/issues/748)): the arguments are already on the stack where the callee's locals go, each keyword moves to its parameter's slot (or is already there, when the site writes them in the order their slots follow the positionals), and an optional parameter the site leaves out gets the undef marker its guarded default looks for. Such a plan is its own guard ([#746](https://github.com/ar4mirez/spinel/issues/746)): beside the class object it was made for it records that class's serial then, and what the entry's method says — the lexical scope of its `def`, the class it was found on, and whether the site may call it whatever the receiver or only when the receiver is the caller's `self` — so a call by it reads neither the call site, nor the entry, nor the table of remembered class ids: the receiver's header, the class's serial and the caller's scope's refinement bit, and it binds. That holds because a plan is made beside the entry that answered the call and is replaced and swapped with it, so for as long as a plan is its site's, its class and serial are its entry's. A `yield` of positional arguments to a block, not a lambda, whose parameters are plain required ones is pushed the same way, padding with `nil` and dropping extras as `bind` would. A site that splats takes the same path when it writes no keywords and pushes at most eight values, each splatted one an `Array` (a subclass's too, whose `to_a` Ruby does not ask) or `nil`, and the last argument they come to is not a Hash `ruby2_keywords` flagged ([#751](https://github.com/ar4mirez/spinel/issues/751)): its plan is made for the count the Arrays came to the first time, a call whose Arrays come to another count goes the general way, and once nothing can decline the call the Arrays give way to their elements on the stack, read where they stand, with no argument `Vec` and no handle each. Such a call is answered by its plan's own guards, as a call that splats nothing is, reading the site only for how many values it pushed and which it splats, which the plan does not keep; `f(*x)`, the one splatted value standing for the whole argument list, is spread where it stands ([#751](https://github.com/ar4mirez/spinel/issues/751)). A `return` that no `ensure` has to see pops its frame in place rather than through the unwinder; `run_calls` does that inline, writing the value to the slot at the frame's floor ([#746](https://github.com/ar4mirez/spinel/issues/746)). For a frame a fast path's plan pushed, whether that holds wherever the `return` stands — the frame is its own `return` target, and its body has no catch table and is not an `eval` string's — is asked of the body once, when the plan is made, and kept on the frame in a byte the 128 leave free, rather than asked of the frame's ids, its body's catch table and its `eval` mark at every return ([#746](https://github.com/ar4mirez/spinel/issues/746)). Anything else takes the general path, unchanged, and that is where every error and every rule the fast paths skip is decided.
- A frame is a fixed 128 bytes and is written where it goes rather than built aside and copied, which every call and return paid for: the parts only some frames ever set — a `catch` tag, the exception a `rescue` handles, what an `ensure` parked, a refusal boundary's limit, a native's name for the frame — live in one out-of-line box made the first time one is set, and a frame holds its `Iseq` by a pointer rather than an `Arc`, since the heap's call caches keep every `Iseq` a frame has entered for the life of the heap. That saves an atomic increment and decrement, of a count shared across Ractors, on every call and return.
- The instructions most loops are made of — pushes, `Pop`, `Dup`, local reads and writes, jumps, a cached `GetIvar`, a fixnum `BinOp` — neither allocate, nor root, nor change the frames, so after one runs the loop runs the ones that follow in a tight inner loop of its own (`light_stretch`) without the work it does between other instructions: rooting what an instruction left on the stack, which only an instruction that can collect needs done first, and looking at the frames ([#747](https://github.com/ar4mirez/spinel/issues/747)). Anything else goes back unrun. A light `SetLocal` of a heap value goes back too, since only a rooted value may be stored below the operands. The budget is still counted per instruction but compared at a backward jump, as CRuby checks for interrupts at a backward branch, so a turn check or a deadline comes at most one stretch of a body late. A run that stops at a call the fast paths above take goes on into it (`run_calls`), and into the light stretches of the frames it reaches and the returns from them — from the frames it pushed and, under the conditions `run`'s own arms take a return, from those below the one it started in ([#746](https://github.com/ar4mirez/spinel/issues/746)) — when nothing the loop does at a call or a return is waiting — a collection or finalizer asked for, tracing, a turn owed, a refusal boundary — none of which a stretch or such a call can start ([#748](https://github.com/ar4mirez/spinel/issues/748)). That holds because the fast paths never allocate: a receiver or block whose class is not already remembered, or a receiver whose class is `Class`, which may need a singleton made, is declined for the general path, which runs after the loop has rooted the stack. The one allocation `run_calls` makes is an Array literal's, `[left, right]` between two calls, and it roots what is fresh on the stack first, as the loop would; a collection that queues finalizers ends the run, so that the loop runs them at the call or return it would have ([#751](https://github.com/ar4mirez/spinel/issues/751)). Both of a literal's cells are made after one threshold check, written once, from the stack, without a `Vec` between, under one handle, the Array's; the storage is exactly as long as the literal, as CRuby's `rb_ary_new_from_values` makes it, so a short literal's two cells are of one size class and, as a rule, next to each other. That is asked only at such a stop, so a run that stops at anything else pays nothing for it. `run_calls` runs the stretches of the frames it reaches inline, in a loop of its own (`calls_loop`), one copy for bodies whose stretches run in `more_stretch`'s loop (below) and one for the rest, handing over to the other copy at a frame of the other flavour: a stretch of its own function made each Ruby call end two functions and begin two, each with a prologue loading the frame's fields, an epilogue, and the instruction it stopped at handed back through memory and dispatched on again ([#746](https://github.com/ar4mirez/spinel/issues/746)). The stretch `run` runs itself is the same small function as before, so that its light instructions keep their registers. The operator masks a stretch works out — which of `Integer`'s and `Float`'s operators the program has left native — are kept from one stretch of `run_calls` to the next for a frame with the same lexical scope and body, rather than worked out again at every call and every return ([#746](https://github.com/ar4mirez/spinel/issues/746)): a mask depends only on those and on what the program has defined, and nothing `run_calls` runs can define a method or activate a refinement, nor can another Ractor write the class tables before this one's next safe point, which is in `run`. They are kept under one word, the frame's scope and cache base together, which a stretch's start compares in one register; every cache base is below `u32::MAX`, so the word for no frame is one no frame has. Which flavour a frame's stretches run in is asked of the heap's call caches only when the running body changes, or after `calls_more` has answered a Float operator, the one thing in `run_calls` that changes a body's flavour; the `more_stretch` copy asks after every step, where keeping the last body asked about cost `nbody` more than the lookups it saved ([#746](https://github.com/ar4mirez/spinel/issues/746)). Whether a return went below the frame `run_calls` started in is told by the count of frames left against the count it started with, not a count of the frames pushed raised at each call and lowered at each return. A direct plan's call has nothing on the stack above its receiver but its arguments, so they move over the receiver in a window that is the rest of the stack, and the stack's length is the one bound checked; a return writes the frame's value at its floor and sets the length there, without a truncation's compare ([#746](https://github.com/ar4mirez/spinel/issues/746)). `calls_loop` tests for a call and a return, the two instructions a stretch stops at most often, with a compare each, ahead of the jump table its other arms take. The call loop's stretches and `more_stretch`'s match an instruction where it stands in the body, each arm reading only its own fields: copied out first, as it was, all five fields of an `Insn` were read ahead of the jump table at every dispatch and held the registers they went to. `light_stretch`, the loop `run` enters itself, still copies it: matched in place there, the loop ran out of registers and kept the body's address on the stack, a load on the path of every dispatch, `getivar` 9% more cycles than main in fewer instructions. A stretch makes no room on the operand stack ahead of its run, since every push checks the capacity anyway and grows it the few times it is reached, and the panic a bad operand index raises is out of line, with its arguments passed by value, where the message formatted in line had every local read store the index and the length first ([#746](https://github.com/ar4mirez/spinel/issues/746)). `run_calls` also answers, as `run` answers them, the instructions `run` answers before its closure that a stretch does not take — a symbol literal, a cached constant read, Float arithmetic, a cached instance-variable write — and a local set to a heap value, rooting what is fresh on the stack first where the instruction stores a heap value, rather than going back to `run` for each ([#750](https://github.com/ar4mirez/spinel/issues/750)). So is the `SplatArray` of `f(*a)` when `a` is `nil` or an Array, which spreads as it is and so leaves the stack alone, so `item_check(*left)` does not leave the call loop ([#751](https://github.com/ar4mirez/spinel/issues/751)). It is answered there rather than among the light instructions because a further arm in `light_step` slowed every light loop, `getivar` 2.4% in instructions. When the instruction after one `calls_loop` answers is itself one it answers — the `Send` after that `SplatArray`, the `Leave` after an Array literal, the literal after the return of the call that made its last element — the loop dispatches on it next, rather than entering a stretch that would stop at it at once and only set up and put away ([#751](https://github.com/ar4mirez/spinel/issues/751)); it does not ask at the start of a body a call has just pushed, nor in the `more_stretch` flavour, where the question cost `fib` and `nbody` more than it saved them. A send that pushes a frame gives the receiver it moved off the stack into that frame a handle, which the loop's rooting of what is fresh on the stack would otherwise have given it — unless the receiver is the caller's own `self`, which every frame's receiver is rooted as already, from its push or the last release ([#746](https://github.com/ar4mirez/spinel/issues/746)); the arguments stay on the stack as the callee's locals, for the next such rooting, and nothing before it can collect. A call the fast path declines goes back to the loop, which goes straight to the general path for it rather than asking again. A call and a return compare the budget, since a recursion may have no backward jump. A fixnum `BinOp` also runs the `SetLocal` or conditional jump right after it. Float arithmetic on two flonums whose answer is immediate, a Float literal that fits a flonum (`Insn::PushFloat`, the double's bits), a symbol literal, a cached `SetIvar` of an immediate and a cached lexical or top-level `GetConst` are light too, but in a stretch of their own, `more_stretch` ([#750](https://github.com/ar4mirez/spinel/issues/750)): every instruction the light loop runs is code in each loop of light instructions, and these, measured in instructions retired, cost the loops that never run them 2% to 5% — inline, out of line, or called from outside the loop. So `run` answers each of them before its closure, and a body's stretches run in `more_stretch` once `run` has answered Float arithmetic in it, which the heap's call caches remember per body; every other body's stretches are the ones they were. In `more_stretch`'s loop the Float operators and literals answer in the loop itself, under `Float`'s operator mask worked out once per stretch as `Integer`'s is, and an operator pairs with the `SetLocal` or conditional jump after it as a fixnum's does ([#750](https://github.com/ar4mirez/spinel/issues/750)). An operator whose left operand is a flonum, a superinstruction's included, asks `Float`'s mask alone and goes straight to `Float`'s operator, without trying `Integer`'s first: two fixnums never take that way, and a fixnum and a flonum are answered by neither, so the general path sees what it saw before, and a redefinition of either class's operator is heard as before. A cached `SetIvar` of an immediate there writes through the view of `self` that a light `GetIvar` takes, when the site's entry names the shape the view saw, looking at `self`'s header only to see that it is neither frozen nor chilled, rather than through `run`'s answer out of line: nothing a light run does freezes an object or changes its shape ([#750](https://github.com/ar4mirez/spinel/issues/750)). Whether a body is the core library's, whose operator instructions answer whatever a program redefined, is decided once per body in the heap's call caches rather than by comparing its path at every stretch ([#746](https://github.com/ar4mirez/spinel/issues/746)). An assignment whose value nothing reads compiles to the value and its `SetLocal`, without the `Dup` and `Pop` around it, as YARV compiles it. So does an `if` or `unless` whose value nothing reads: each arm's statements are discarded in turn, so a missing arm pushes no `nil` and nothing is popped after it, and `x unless c` is one `JumpIf` around `x` ([#746](https://github.com/ar4mirez/spinel/issues/746)). So does a multiple assignment whose value nothing reads, of an array literal with no splat into distinct locals and instance variables with no `*`: the values are pushed in order and popped into the targets last to first, a missing one `nil` and an extra one evaluated and dropped, rather than built into an `Array` and spread by `Array#__masgn_spread__` ([#750](https://github.com/ar4mirez/spinel/issues/750)). Nothing can tell the order of the writes apart, since every value is evaluated first and neither kind of write runs Ruby code; two targets naming one variable would, so such a statement is spread.
- A call to a primitive with a light form — `String#<<` of a String whose bytes go on as they are, or of an Integer that is one byte of the receiver's encoding as it stands (any byte of a BINARY String, an ASCII one of a UTF-8 or US-ASCII String: [#879](https://github.com/ar4mirez/spinel/issues/879)); `Kernel#nil?` ([#751](https://github.com/ar4mirez/spinel/issues/751)), whose site, when it calls `nil?` by that name rather than an alias, also answers `nil.nil?` with `true`, without the frame `core/nil_class.rb`'s `NilClass#nil?` would push or bringing `nil`'s entry in front, for as long as a lookup still finds the public body the core library defined, the guard `Integer`'s and `Float`'s operators have beside it, which is CRuby's `opt_nil_p`, and with no `TracePoint` enabled and no refinement where the call is written; and since [#750](https://github.com/ar4mirez/spinel/issues/750) an `attr_reader`, `Array#[]` with an index, `__reflect_kind_of__` (`Module#===`'s question) for an object whose class is known, and `__math__` of fixnums and flonums with a flonum answer — is answered where it stands on the operand stack, without the `Pending`, the argument `Vec` or `dispatch` ([#749](https://github.com/ar4mirez/spinel/issues/749)). Its site's plan says so, made the first time the inline-cache entry answers a call, for a public primitive, or a private one called with no receiver written, which passes the visibility check every time, and a site passing positional arguments alone; each call checks the receiver's class by its header, that class's serial against the one the plan was made at, as a `Direct` plan's is, a refinement where the call was written, and that no warning or redefinition is waiting for `dispatch` to say, and the light form then reads its operands by value and declines anything it does not take — a frozen or chilled receiver, an argument that is neither, encodings that do not let the bytes on as they are — which goes the general way, warm or not. Without leave to allocate it also declines an append its receiver's buffer has no room for, which is how `run_calls` asks it, with the stack not yet rooted; `run`'s own arm, after its rooting, takes that one and grows the buffer. After `run_calls` answers one it goes on in `native_stretch`, a loop of light instructions of its own that answers each further such call in the frame where it stands, and runs the `Pop` after one whose answer nothing reads, so that a loop around an append stays in it; it is a separate function so that `light_stretch` and `calls_loop`'s stretches, which every other frame runs in, keep their registers, inlined into the one `calls_loop` calls for the light form, which is out of line already, rather than a call of its own after it ([#751](https://github.com/ar4mirez/spinel/issues/751)). A frame whose stretches run in `more_stretch`'s loop runs every stretch `run_calls` reaches in it in that loop instead (`more_native_stretch`), with the operator masks kept as `calls_loop`'s stretches keep them, and sets a local to a heap value there too, once it has rooted what is fresh on the stack, while the handles held stay within the number `run` lets pile up before it releases them ([#750](https://github.com/ar4mirez/spinel/issues/750)): so a loop of Float arithmetic over objects read out of an Array, `b = bodies[i]; dx = @x - b.x`, stays in one stretch across `bodies[i]`, the `SetLocal` of `b` and each `b.x`, rather than leaving one and entering another at each. That loop is inlined into its flavour of `calls_loop`, as the other flavour's stretches are, so a Ruby call from such a frame stops paying a function's prologue and epilogue for the stretch after its push and the one after its return; the loop reads a `Send`'s plan once, goes straight to the primitive's light form for a `Native` one and stops at once for a call of a Ruby method; and it keeps the view of `self` its `GetIvar`s read through across a light form, which allocates nothing and assigns no instance variable, pointing it at the ivar caches again after the call, since an `attr_reader`'s miss fills one, rather than making it again at the next `@y` ([#750](https://github.com/ar4mirez/spinel/issues/750)). A cached constant read answers in `more_stretch`'s own loop, as a Float literal does, rather than through `run`'s answer out of line, and `__math__`'s light form finds its operation by the name's symbol id among ids interned once per process (`shared/symbols.rs`, as `always_private` is), rather than by its bytes read under the symbol table's lock, two atomic operations a `Math.sqrt`. The other flavour keeps `calls_loop`'s own stretches, as before; the light-form call that hands its masks over is a function of its own for each flavour, so the other's call loop compiles as it did. A primitive pushes no frame either way, so a backtrace is the same.
- A method body is a definition id — a fixnum indexing a per-heap table of `Iseq`s and primitives — rather than a heap object, because the heap has no payload kind that holds a Rust `Iseq` and no finaliser to drop one. A fixnum body is also one the collector never traces.
- `break`, `next`, `redo`, `return` from blocks, and `throw`/`catch` are all non-local exits through the same unwinding path as exceptions, with catch tables per bytecode range, like YARV and the JVM. As landed in #12: one `Unwind` value travels up the frame stack and one search decides where it stops — a `rescue` range whose handler accepts the class, the frame `catch` opened for a tag, or the frame a `break` or `return` named by id. Frame *ids*, not depths, because a `Proc` can outlive its call and a depth would be reused; a target that is no longer on the stack is `LocalJumpError`, which is Ruby.
- An `ensure` body is compiled **once**, not twice. YARV emits one copy inline for the normal path and another as a handler, and pays for it with two versions of any `break` or `return` written inside one. Spinel enters it through the same door either way: `EnterEnsure` parks the reason on the frame — a value on the normal path, an unwind in flight otherwise — and `LeaveEnsure` either restores the value or resumes the unwind. "Runs on every exit path" is then a property of the search rather than of keeping two copies in step.
- A jump *within* a frame that leaves an `ensure` goes out through the unwinder too (`Insn::Goto`), because a plain jump to a loop's end would step straight over the `ensure` body. Only the ones actually being left are run: the search skips any entry whose range still covers the jump's target, which is what keeps `begin; while c; next; end; ensure; E; end` from running `E` once per iteration, and any entry whose range *ends* at the target. That end is the `EnterEnsure` the body falls into, so a jump landing there arrives at the normal door, which runs `E` itself: `begin; while true; break; end; ensure; E; end` — the shape WEBrick's `GenericServer#start` leaves its accept loop by — used to run `E` twice, once from the unwinder and once on arrival.
- A raise becomes an exception object at exactly one place, where `Error::Raise` leaves an instruction. What does *not* become one is `Error::NoDispatch`, `Error::Budget`, and `Error::Unknowable`: those say the VM cannot run the program rather than that Ruby raises, and a `rescue` that caught them would let an example carry on down a branch Ruby never takes. A *missing method* used to be in that list and is not since [#170](https://github.com/ar4mirez/spinel/issues/170): it is Ruby's own `NoMethodError`, rescuable, built at the dispatch site rather than at that one place because it carries `@receiver` and an `Error` holds only strings. The branch-Ruby-never-takes problem is real: an example that swallows a missing method in a `rescue` and then misses an expectation is reported failed. `spec/harness` reported it blocked, from a record the heap kept of the gap; mspec has no such rule, so such an example is tagged with the missing method as its reason. The exception hierarchy itself is measured from CRuby by `scripts/exceptions-oracle.rb` into `src/exceptions.txt`, including which classes define an `initialize` of their own — Spinel implements only `Exception#initialize`, so `new` on one of the others refuses rather than answering as though it had validated arguments it never looked at.
- Fibers own a VM stack. Switching fibers is switching which VM stack the interpreter loop uses. Because the interpreter is non-recursive and the core library is in Ruby, almost no fiber switch happens with Rust frames in between. Where a primitive must call back into Ruby (a sort comparator, `Hash#each` primitive fallback), the re-entrant call runs on a `corosensei` coroutine so the fiber can still be suspended. The heap's root stack is what the GC scans, and a suspended coroutine keeps its own region of it, so the GC still sees every handle. `Enumerator#next` comes from this for free, and so does the Fiber scheduler's switching ([#797](https://github.com/ar4mirez/spinel/issues/797)): `core/fiber.rb` keeps one scheduler per thread, current only in a fiber that is not blocking, and `sleep`, an IO's waits, reads and writes and `IO::Buffer#read`/`#write` hand themselves to its `kernel_sleep`, `io_wait`, `io_read`, `io_write`, `io_pread` and `io_pwrite` there, each IO hook with a locked `IO::Buffer` over the bytes, as CRuby's `rb_fiber_scheduler_io_read_memory` makes one. Sending the write buffer is `write(2)` itself, as CRuby's flush is. A thread's scheduler is closed when its block returns, the main thread's before the `at_exit` blocks. `block`/`unblock` for `Mutex`, `Queue` and `Thread#join`, `io_select`, `process_wait`, `address_resolve` and `timeout_after` are not asked yet.

## Core library

**Decision:** core classes are Ruby on primitives. `core/string.rb` defines `String#upcase` in Ruby using primitives like `Primitive.string_bytes(self)`. The rule for what becomes a primitive: raw memory, allocation, encoding tables, syscalls, dispatch, and anything the JIT needs as an intrinsic. Everything else is Ruby.

Boot order:

1. `spinel-vm` creates the heap and the bootstrap classes `BasicObject`, `Object`, `Module`, `Class`, `Kernel`, `Comparable`, `Enumerable`, `Numeric`, `Symbol`, `String`, `Integer`, `Array`, `Hash`, `Proc`, `Exception`, `Regexp`, `MatchData`, `NilClass`, `TrueClass`, `FalseClass`, `Float` as empty shells with the right ancestry. The three modules and `Numeric` are on the list because of "the right ancestry": without them `Integer.ancestors` is wrong from the first commit, and `core/*.rb` cannot fix an ancestry it is loaded into. The last four are on it because `nil`, `true`, `false` and a flonum are immediates whose class is decided in `class_of` rather than in a header, and a value with no class has nowhere to dispatch `to_s`.
2. Rust primitives are registered on the classes they belong to.
3. `core/*.rb` is loaded and executed, filling in every method.
4. Core classes are marked shareable. Any Ractor may reopen them under the class lock, as in CRuby 4.0.9, which refuses a non-main Ractor only a class instance variable or an unshareable constant (see "Ractors and threads").

Steps 2 and 3 are `spinel-core`'s, not `spinel-vm`'s, and the split is a layering one: compiling Ruby needs a parser, and `spinel-vm` does not depend on `spinel-parse` because Prism lives in exactly one crate. So the VM bootstraps *classes* and `spinel-core::boot` bootstraps their *methods*. Every embedder calls both, in that order.

As of [#15](https://github.com/ar4mirez/spinel/issues/15) step 3 compiles `core/*.rb` on the first boot in a process and caches the `Iseq`s, rather than reading a precompiled image. Evaluating per heap is unavoidable — a method table belongs to a heap, and a test may make one heap per case — but parsing per heap is not, and the cache is what keeps a 25,000-example run from paying for Prism 25,000 times. An `Iseq` is immutable and holds no `Value`, so the cache is the same category as `shared/symbols` rather than the process-global VM state `CLAUDE.md` forbids.

`// ponytail:` that cache is `core.image` minus the serialisation. The ceiling is one parse and compile per process; the upgrade is a `build.rs` that serialises the `Iseq`s into the binary, worth writing when that parse shows up in a benchmark.

**`x.nil?` in `core/*.rb` is an identity test, not a send** ([#924](https://github.com/ar4mirez/spinel/issues/924)). The core library stands in for CRuby's C, which asks `NIL_P` and never a Ruby-level `nil?`, so `compile::core_program` compiles a `nil?` with a receiver, no arguments and no block to a `JumpIfNilKeep` that pushes `true` or `false`. A program that makes `NilClass#nil?` private, redefines it or removes it changes nothing in how `rescue` builds and matches a `NoMethodError`, or in any core method that tests for `nil`. A program's own `nil?` is a send as before: `Kernel#nil?` answers `false` for every receiver, `nil` too, as CRuby's `rb_false`, and only `NilClass#nil?` answers `true` ([#923](https://github.com/ar4mirez/spinel/issues/923)).

**Primitives are installed under their Ruby names**, on the class that owns them, rather than under a hidden `Primitive` module. There is no `Primitive` module yet: it would need a name, a bootstrap entry and a documented surface before anything needed one, and every primitive so far *is* the Ruby method — `Array#[]` is the slot read, `String#+` is the allocation. The ones that are not carry a `__` name — `__fd_read__`, `__fs_stat__` — and are each one system call or one table read that the Ruby method around them is written on. `Kernel#__write__`, which wrote a String to stdout before there was an `IO`, was the first; #41 deleted it, and `$stdout` is a descriptor like any other. `Hash`'s three slot accessors were another, and #151 deleted them: it reads its own instance variables now.

**`Array` is two slots: storage and length.** A heap cell cannot grow, so an array whose elements live in its own slots could only grow by becoming a different object and Ruby would see the identity change. The elements live in a separate `Payload::Slots` object instead, and growing replaces *that*; the `Array`'s own address never moves. This is `RARRAY`'s pointer and length, for the same reason. The length slot also holds a head offset, where the live elements start in the storage: `shift` moves it up rather than copying the rest down, and `unshift` moves it back into room left at the front, so both are amortised O(1) as CRuby's shared arrays make them (#733). `String` has the same indirection over a byte payload (#19), which is how `String#<<`, `#concat` and `#replace` change a String in place.

Strings (default): a byte buffer, a byte count, an encoding index and an offset into the buffer (`strings.rs`, #19) — the buffer is a separate object so a String grows in place. A long slice shares its source's buffer at an offset, as CRuby's `rb_str_subseq` does, so `byteslice` and `[]` cost one cell whatever its length (#619): at least 64 bytes and at least half the buffer, which bounds what the buffer it keeps alive and the copy a later write makes by the copy it saved. Sharing freezes the buffer cell, which Ruby never sees, and a String on a frozen buffer copies its own bytes out before its first write. Characters are walked in UTF-8, US-ASCII, ASCII-8BIT, ISO-8859-1, UTF-16 and UTF-32, the encodings `encode` converts between arithmetically (`transcode.rs`, PRD 0050), in EUC-JP, Shift_JIS and Windows-31J, whose lead and trail bytes are ranges (#339) and which `encode` converts by CRuby's table (`jis.rs`, #378), in CESU-8, UTF-8 with a codepoint past U+FFFF spelled as its surrogate pair (#344), in every other single-byte encoding that is not a dummy — every byte a valid character of its own, measured (#372) — the code pages among them, ISO-8859-2 to -16, KOI8, the Windows, IBM and Mac ones and TIS-620, which `encode` converts by CRuby's table (`codepage.rs`, #41) — in every other ASCII-compatible multibyte encoding that is not a dummy, Big5, CP949, EUC-KR, GBK, GB18030, EUC-TW, Emacs-Mule and the variants, bounded as the regex engine reads them (#388) — EUC-KR of these `encode` also converts by CRuby's table (`euckr.rs`, #725), and GBK, GB18030, GB2312, GB12345, Big5, Big5-HKSCS, Big5-UAO, CP950, CP951, CP949, EUC-JIS-2004 and eucJP-ms by CRuby's tables (`cjk.rs`, #796) — and in a dummy encoding, ISO-2022-JP among them, a byte each and every byte valid, as CRuby reads them (#404). `encode` converts along CRuby's path of converters, a character at a time through each, so an error names the converter that refused it; ISO-2022-JP goes through stateless-ISO-2022-JP and EUC-JP, keeping its escape state between steps (`iso2022jp.rs`, #404), and CP50220 and CP50221 through CP51932, whose table is Windows-31J's first 94 rows, keeping G0 and the katakana CP50220 holds for a voiced mark (`cp5022x.rs`, #419). Their decoder passes a byte from 0x80 to 0x92 on as it is, so CP51932's reader takes a byte stream there, not characters: the bytes a character has only begun, and those an error gives back, wait in the step state for the next (#684). From one of the two to the other, where that reader is the encoder and CRuby inserts a replacement after all it has still to read, `encode` runs `Encoding::Converter`. No cached character count yet: `length` walks the bytes, which is the first thing to add when a benchmark asks. No ropes.

The default external encoding is the locale's, as CRuby's is (#41): `Encoding.locale_charmap` is `nl_langinfo(CODESET)` for the locale `LC_ALL`, `LC_CTYPE` and `LANG` name, read once, and `Encoding.find("locale")` is the encoding of that name, UTF-8 for a name no encoding has, as `rb_locale_encindex` falls back. `default_external`, and with it `find("external")` and `find("filesystem")`, is that encoding unless `-E` or `default_external=` sets another. Under any UTF-8 locale everything is UTF-8; under `LANG=C`, POSIX or no locale at all it is US-ASCII, so `File.read` returns US-ASCII strings, `$0` and `ENV` are US-ASCII (BINARY where their bytes are not ASCII), and `Dir.pwd` is BINARY, each measured on ruby 4.0.9. `ARGV`'s elements are frozen and in the default external encoding, tagged again once `-E` or `RUBYOPT=-E` has set it, so `LANG=C spinel -E UTF-8` gives UTF-8 arguments, and transcoded into the default internal encoding when `-E ext:int` names one, an argument that does not convert left as it was, while `$0` stays in the locale's. `scripts/spec.sh` runs the corpus under `LC_ALL=C.UTF-8` (`en_US.UTF-8` on macOS, which has no `C.UTF-8`) so its counts do not depend on the machine's locale. Two places still assume UTF-8 whatever the locale: `__FILE__`, a literal the compiler makes, which CRuby gives the filesystem encoding, and a `-e` program's source, which CRuby reads in the locale's encoding.

`IO::Buffer` (#797) is Ruby, `core/io_buffer.rb`, keeping CRuby's four facts — base, size, flags, and the source a slice was cut from — in hidden instance variables. An INTERNAL buffer's memory is a hidden BINARY String; one `for` or `string` makes is the program's String, which is locked while the block runs: a locked String carries both chilled header bits, a pair no chilled String has, so the light forms decline it and `__unchill__`, which every mutator's `__modify__` reaches, raises "can't modify string; temporarily locked" (`heap.rs`, `TMPLOCK`). A MAPPED buffer's memory is `mmap(2)`'s, in a per-heap table keyed by address that bounds-checks every read and write (`iobuf.rs`), unmapped by `free` or by the finalizer of the object that owns it.

Hash (default): insertion-ordered open addressing, keyed on `#hash`/`#eql?` with fast paths for Symbol, String, and fixnum keys.

Regex is `spinel-regex`, this engine's own (see below).

## Metaprogramming

Supported from the phase it is needed, never designed out: `send`, `respond_to?`, `method_missing`, `define_method`, `instance_variable_get/set`, `instance_eval`, `class_eval`, `Module#include/prepend/extend` with correct ancestor linearization, `const_missing`, `inherited`/`included`/`method_added` hooks, `ObjectSpace.each_object`, which walks every cell and reports each object with a class (#36). String `eval` works because Prism is in the binary, reached through a parser hook `spinel_core::boot` installs so the VM crate never links it. The hook is told the string's encoding, which a string with no magic comment is read in, as CRuby reads it (#337). `binding` and `Binding#local_variable_get` come with it: every block `Iseq` keeps the local names of the scopes around it, which is the name-to-slot map a frame's environment needs (PRD 0051). `caller`, `caller_locations`, `Method#source_location`, and `__method__` come from frame metadata. `ObjectSpace::WeakMap`, `WeakKeyMap` and `ObjectSpace.define_finalizer` landed with weak references in the GC (#36). The `WeakRef` library is built on `WeakMap`, over `delegate.rb`'s copy of `Kernel` — `Module#dup` (#28). `TracePoint` for `:class`, `:call`, `:return`, `:line`, and `:raise` came in phase 7 because Zeitwerk and debuggers need it (#127, below). Refinements (#352) hang off the lexical scope, as CRuby's `CREF_REFINEMENTS` does: a cref node points at a table of active refinements, `using` gives the caller's frame a copy of its node with the module's added, and a send from a scope with any active walks the receiver's ancestors asking at each one whether an active refinement of it defines the name, before its own table. Such a send skips the inline caches, which cannot say which scope they answered for. A `refine` block's scope has every refinement its module makes active, made before or after it; a refinement's `super` goes on to the class it refines.

**Built so far for `TracePoint` (#127):** the five events, in `core/trace_point.rb` over four primitives: the events, a frame's binding and its parameters, and a target's bodies. The enabled `TracePoint`s of a Ractor are a list on its `TracePoint` class object, newest first as CRuby connects them, and `Kernel#__trace_events__` gives the heap the union of the events they wait for. The bytecode is never rewritten, since it is shared between Ractors; what changes is how the loop runs it. While that union has `:line` or `:return`, which can come at any instruction, the loop pins its limit at the maximum, as allocation tracing does, so every instruction goes through `tracepoint_step` before it runs, and it leaves every path that could carry it past an event: the light stretches and `run_calls`, the inline sends, yields and returns before the closure, and a superinstruction's run, which declines to its first instruction. That is the interpreter's deoptimisation. There is no compiled code to throw away yet, since the JIT is phase 6, and the loop takes its fast paths back at the first call or return after the last such `TracePoint` is disabled. `:class`, `:call` and `:raise` need none of it (#908), so a `TracePoint` a program keeps enabled for its whole life, Zeitwerk's `:class` or an error tracker's `:raise`, costs only the frames it fires in. A method's or a class body's frame is pushed marked as owing its event, and the loop's frame-change block, which every push passes through before the frame's first instruction, fires it there; a `:raise` fires where the exception starts, which is the loop's own, and an event the unwinder parks on a frame fires at the frame-change block it forces. While a `TracePoint` waits for `:call`, the fast paths that push a method's frame without that block seeing it, `run_calls` and the inline sends, are off, since they do not mark it. `run_calls` stays on for `:class` and `:raise`, but stops at a return into a frame whose event has not fired yet, which a class body is under the `inherited` hook that runs first, and at one out of a hook's frame, whose caller may have an unwind parked on it. An event is a call to `TracePoint.__fire__` pushed on top of the frame it happened in, as a finalizer's is, so a hook runs in the same loop and sees that frame's binding. The frame comes back to the same instruction when the hooks are done, and `Rare::trace_done` records which events it has already fired there. A hook runs with its thread's `__tracing__` set, so the events of its own code fire nothing until `TracePoint.allow_reentry`, and with `$!` nil, which the hook frame's pop gives back. Nothing fires in a core-library frame, which CRuby's C is.

- `:line` fires where the compiler recorded one in `Iseq::line_events`: before the first instruction of each statement of a statement list, and of each `if` or `unless`, whose line no statement of the same body has started yet. That is Prism's newline flag with `prism_compile.c`'s `last_line`, measured on CRuby 4.0.9. A `begin` and a parenthesised list fire nothing of their own, a lone statement in `#{}` fires none, nor does the lone statement of an endless `def` (`def f(x) = x + 1`), and a `while` or `until`, whose test is its first instruction here but CRuby's jumps to it once, fires only on the way into the loop, not from its own jump back.
- `:call` and `:class` fire before a method's or a class body's first instruction, from a `Call::trace` bit the frame was pushed with while one was enabled. `class << obj` fires no `:class`, as in CRuby 4.0.9. A `define_method` body is a method here, as CRuby's bmethod is.
- `:return` fires before a method's `Leave`, which the compiler puts on its `end` line, or, when an unwind leaves the method, from the unwinder. The unwinder cannot push the hook's frame, so it parks the event and the unwind on the frame and the loop fires the event; the unwind goes on at the next frame change, whether or not the hook left anything enabled. The value is what a block's `return` that ends the method carries, and nil for an exception, a `break` and a `throw`. After an `ensure`, the line is where the unwind left the body.
- `:raise` fires where an exception starts, before the unwind, with the unwind parked the same way. When the core library started it, the event is owed to the program's frame below and fires if the unwind gets there, reporting the core method's receiver and name, as CRuby reports a C method's. An exception the core library raises and rescues itself fires none, as CRuby's C never raises it.

`enable(target:, target_line:)` hooks the events of a method's or a `Proc`'s body and every body written inside it, identified by `Iseq` address, through `Kernel#__trace_target__`, which also counts where an event can fire, so that a target with none raises CRuby's "can not enable any hooks". Asking for any other event refuses rather than giving a hook that silently never runs. Spec delta: `core/tracepoint/` 0 → 55 of 76, and the 21 left are the other events'. `crates/spinel-cli/tests/tracepoint.rs` holds four programs to CRuby's output, byte for byte: three to 4.0.9's, and `floors` (#908), the `:class`, `:raise` and `:call` floors around warmed-up code, to 3.4.10's. Among them is a loop on every fast path, warmed up and then traced from a call it makes partway through.

## Ractors and threads

**Decision:** Ractor-native. A Ractor is a heap plus a lock plus one or more OS threads. Threads in the same Ractor take turns under the lock, releasing it around blocking IO, like a per-Ractor GVL. Ractors run in parallel.

Shared, immutable, append-only tables live in `spinel-vm/src/shared/`: the symbol table and frozen string literals. So do the primitives' method tables (`shared/primitives.rs`, #652), which the first heap to bootstrap builds and every later bootstrap copies into its classes instead of interning each name and inserting each method again. A name there is a `SymbolId` and a body is the fixnum index of a definition, which every heap's bootstrap adds in the same order, so the tables hold no heap object. So does the one table that is neither, because the operating system puts it there: the count of each signal that arrived and waits to be handled (`shared/signals.rs`, #44). The OS handler only adds to it and writes a byte to a wake pipe; the main Ractor's main thread takes from it at a safe point — the interpreter's turn check, or the scheduler's `poll(2)` — and runs the Ruby handler there, never in the OS handler. It holds no `Value`. Two locks sit there for the same reason, since what they order is the C library's process-wide state (#119): `shared/env.rs`, CRuby's `env_lock`, which every `ENV` read and write takes around its call into the environment, and `shared/services.rs`, which serialises `getservbyname(3)` and `getservbyport(3)` where the platform has no reentrant `_r` variant (Linux has them, and takes no lock). Each is a `Mutex<()>` guarding calls, holding no `Value`. Classes and modules are also shared, but they are not immutable, so they are not in `shared/`: a program's class table, its method bodies and the class lock that guards them are one `Vm` (`spinel-vm/src/vm.rs`), which the main Ractor's heap makes and every other Ractor's heap joins (#117). Every Ractor reads them, and every Ractor may write them under the class lock: CRuby 4.0.9 lets a non-main Ractor define methods and classes and set a constant to a shareable value, and of the tables' writes raises `Ractor::IsolationError` only for setting a class's or module's instance variable (`can not set instance variables of classes/modules by non-main Ractors`), a class variable, which such a Ractor may not read either (`can not access class variables from non-main Ractors`), or a constant to an unshareable value (`can not set constants with non-shareable objects by non-main Ractors`). ruby/spec has no Ractor specs at all, so those rules are measured on 4.0.9. Everything else is per heap. A thread that does not hold its Ractor's lock is parked, so the GC can treat parked threads' VM stacks as roots without stopping the world.

The lock is released around blocking IO, `sleep`, `Queue#pop`, `Mutex#lock`, `IO.select`, and FFI calls declared `blocking: true`. Sending an object to another Ractor copies it or moves it. In CRuby a shareable object (frozen deep, or an immutable table) passes by reference; here it passes as a frozen copy, since no heap holds a pointer into another's (#117, decision 2a): `equal?` and `object_id` tell it from the sender's, which CRuby's do not. `ENV` is the one shareable object that is not frozen, as in CRuby 4.0.9 (#865): its header carries the `ractor-shareable` bit alone, and its copy stays unfrozen, keeps `ENV`'s singleton class, so each Ractor's `ENV` has its methods, and carries none of the original's instance variables. Its state is the process's environment, behind `shared/env.rs`'s lock; the table its enumerating methods keep is each Ractor's own, dropped when the count of writes through `ENV` the program keeps (`ractor::Program`) has moved. ruby/spec has no Ractor specs, so the rules are measured on CRuby 4.0.9 and checked by `crates/spinel-cli/tests/ractor.rs`.

**Built so far (#45, #328):** each thread runs on an OS thread of its own, and the threads of a Ractor take turns with its heap under the lock. A thread is a saved pair of the interpreter's vectors plus its own fiber bookkeeping and root stack (`spinel-vm/src/threads.rs`); a switch parks the running thread's, hands the heap to the next thread's OS thread, which takes its own back and runs its own instruction loop over them, and waits to be handed the heap back. The loop preempts the running thread every 10 ms on the same compare as the budget — never inside a core-library frame, so a core method is as atomic as CRuby's C one; a turn check that lands in one leaves the turn owed, and the loop gives it at the call or return that leaves the core library (#728) — and every wait listed above goes through the scheduler, which `poll(2)`s for the first deadline or descriptor when no thread can run and wakes the main thread to raise the deadlock when every thread waits on another. A call that blocks in the kernel without a descriptor the scheduler can wait on — `flock`, `fsync` and `fdatasync`, `open(2)` of a FIFO, a read or write of a blocking pipe or terminal Spinel did not make, `getaddrinfo` — is made outside the lock: its thread is parked as if it waited, another runs, and it gets back in line when the call returns. A pipe Spinel makes is `O_NONBLOCK`, as CRuby's is (#41), so a write to it that would block answers EAGAIN and waits in the scheduler, and a child gets its standard streams blocking. Every call made outside the lock but `getaddrinfo` has an unblocking function, as CRuby's blocking region does (#41): the OS thread making it is recorded in the lock, and a kill or raise for its thread, a signal for the main thread, a `close` of the descriptor it uses and the program's end send that OS thread SIGVTALRM, which Ruby reserves (`trap(:VTALRM)` raises) and Spinel installs without `SA_RESTART` and with a handler that does nothing, so the call answers EINTR. The thread gets back in line, meets what asked (`Thread.__check_interrupts__`, CRuby's `RUBY_VM_CHECK_INTS_BLOCKING`), and makes the call again if nothing raised; a `close` waits for the threads using its descriptor to leave their calls before it closes it, as `rb_thread_io_close_wait` does, and each raises `IOError: stream closed in another thread`. The signal goes again every 10 ms until the thread is back, as CRuby's timer thread sends it, since the first may come before the call enters the kernel. A signal for the main thread is sent on by whichever thread runs the scheduler, since the signal itself restarts what it cuts short. The main thread alone has nothing to send it, so it writes a blocking pipe or terminal only once it has room, waiting in `poll(2)` when it has none, as it waits for one to have a read, and a signal then cuts the write short with what it took; and it waits for a lock with the signals Ruby handles set not to restart what they cut short. `$~`, `$!`, `$_` and `$?` are swapped per thread. `Thread`, `Mutex`, `ConditionVariable`, `Queue` and `SizedQueue` are Ruby (`core/thread.rb`), and the program's end kills the threads still alive once its `at_exit` blocks have run, as CRuby's does. What is left: an FFI call declared `blocking: true` (#105) made through the same unblocking function, a resolver a kill can leave (CRuby 3.3 resolves on a thread of its own), and a signal for the main thread while every thread is outside the lock, which waits until one comes back.

**Built so far for shared classes (#117, part 1):** the class table and the method bodies moved out of `Heap` into the `Vm` above, and a heap reaches them through `classes()`, `classes_mut()`, `definitions()` and `definitions_mut()` as before. What a heap allocates stays its own. A class object is a heap cell, and an instance's header points at a class object of its own heap, so each heap keeps one object per class, indexed by class id (`Heap::class_objects`), and the table is keyed by the id rather than by any heap's object. The core library's hidden instance variables, the `@__name__` spelling, live on those objects, so each Ractor has its own: `Random`'s default generator, `Kernel`'s recursion guards, `Encoding`'s defaults. A heap that joins the program (`Heap::new_ractor`) makes its object for every class there is, and for each class another heap defined since, at its next safe point or when a write it waited for is granted; a class's object gets the class the table records for it (its singleton class, the `Module` subclass a module was made by, or `Class` or `Module`). The table holds a class, in a constant, a class variable or as a singleton's object, by an id-tagged immediate (`Value::class_ref`) rather than by any heap's object, so it holds no pointer into a heap a class crosses to, and the collector passes over it. Every heap, the main one too, reads such a value through `HandleScope::shared_to_local`, which answers its own object for the class and any other value as it is, after one tag check, and writes one through `local_to_shared`, which turns its own class object into the id. The tag never reaches Ruby code. The values the table holds that are neither a class nor an immediate are the main heap's, and only its heap traces them.

The class lock is the other way round from a lock taken per read, as CRuby's VM barrier is, because a read is on every send. A running heap *holds* the lock, and reads the tables taking nothing. A write (`classes_mut`, `definitions_mut`) waits until every other heap has let its hold go at a safe point, writes alone, and lets the others back at its own next one. The safe points are the interpreter's turn check, every 4096 instructions, and the end of an evaluation, and a heap lets its hold go around a wait (`Heap::release_classes`, `reacquire_classes`) and, since #119, around a call made outside the per-Ractor lock while no other thread of it runs. Writes are rare after boot: a definition, an `include`, a constant assignment, a method-cache fill. While a program has only ever had one Ractor none of it runs, since the lock's `shared` flag is false: a write pays one load and a branch, as do a turn check and the end of an evaluation, and a read pays nothing. `crates/spinel-vm/tests/ractor_heaps.rs` runs a joined heap on its own OS thread calling methods the main heap defined while the main heap defines two hundred more on the class its calls go through, and checks that the joined heap sees them all and that its `Object` and its `Integer`'s hidden instance variable are its own; `vm::tests` holds the lock to its rule under Miri. No ruby/spec delta, since nothing a program can see changed: the corpus is unchanged. 

**Built so far for Ractors (#117, part 2):** `Ractor` and `Ractor::Port` are `core/ractor.rb` over the primitives of `spinel-vm/src/ractor.rs`, with CRuby 4.0.9's Ruby 4 API (no `Ractor.yield` or `#take`). `Ractor.new` makes a heap that joins the program (`Heap::new_ractor`, carrying the parser and the program's settings) and an OS thread for it, which runs `Ractor.__child_main__`: its own `$stdin`, `$stdout` and `$stderr` for the same descriptors, then the block, rebuilt in its heap as a `Proc` of the same body and lexical scope with the Ractor as `self`, which `Ractor.new` refuses when it reads a variable outside itself (`can not isolate a Proc because it accesses outer variables (x).`). What every Ractor shares is one registry, which every heap of the program holds beside the `Vm` (`ractor::Program`), out of the `Vm` so the interpreter's loop keeps the layout it was measured with: each Ractor's id, name, state and the value it ended with, and each port's queue; a `Ractor` or a `Port` object holds an id, and two for one are `==`. A value crosses as a copy (`heap/copy.rs`): the sender reads the graph under it, cell by cell, into a `Msg` that holds no heap pointer — a class by id, a shape by its names, a compiled `Regexp` by its program — and the receiver builds it again, then rehashes each `Hash` and freezes what was frozen. A `Proc` (but one made shareable, #118), `Method`, `UnboundMethod`, `Binding`, `Thread` or `Fiber` is refused with CRuby's `allocator undefined for ...`, an `Enumerator` with `can not copy Enumerator object.`, and `move: true` leaves the sender a `Ractor::MovedObject`. A wait (`receive`, `#value`, `#join`, `Ractor.select`) is a thread waiting for a descriptor, the Ractor's own wake pipe beside a generation count, so its heap's other threads run meanwhile, and the scheduler's `poll(2)` lets go of the class lock while it waits, so a Ractor defining a method meanwhile does not wait for it. A Ractor but the main one reads what the tables hold of the main one's as a copy, made while the main heap is parked (it is the lock's writer for the copy) and kept per original, so one object read twice is one copy: a constant the program reads when it is shareable, and otherwise `can not access non-shareable objects in constant Object::S by non-main Ractor.`; a constant the core library reads whatever it holds, which is decision 4a's per-Ractor core constant (`ThreadGroup::Default`, `Encoding::LIST`); a class's instance variable the program reads when shareable (CRuby's `can not get unshareable values from instance variables of classes/modules ...`), the core library's, and every `@__name__` one, as the Ractor's own from a copy of the main one's (decision 3a), except the few that start afresh (which Ractor it is, recursion guards, handlers); and a `define_method` body, which the core library's `Struct` and `Data` accessors are. A constant such a Ractor sets to a shareable object goes in the tables as a copy every heap builds its own of (`Value::shared_ref`), a singleton class it makes keeps the object it is attached to in its own heap, and a `define_method` body it makes is traced by its heap and refused to the others with CRuby's `defined with an un-shareable Proc in a different Ractor`. Class variables and every global but CRuby's per-Ractor ones (`$stdout`, `$VERBOSE`, `$/`, `$~` and the rest) raise `Ractor::IsolationError` there, measured; the core library's own reads of them are CRuby's C, which reads them unchecked. A main heap dropped while another Ractor runs keeps its memory, as the process ends with it. `crates/spinel-cli/tests/ractor.rs` runs eleven programs and compares their output byte for byte with CRuby 4.0.9's. What is left: a Ractor's `require` (CRuby runs it on the main one), and a `Hash` read from a constant keyed by identity rehashed; the class lock let go around a call made outside the per-Ractor lock, and a CPU-bound benchmark scaling with Ractor count, are #119's, below.

**Built so far for parallel execution (#119):** Ractors run at once, each on its OS thread with its heap, and a CPU-bound benchmark's time falls as Ractors are added (`bench/ractors/`, the table in `bench/README.md`, written by `bench/ractors.sh`). What kept them taking turns was the class lock's write, which parks every other Ractor until the writer's next safe point, made on paths every call takes: a send whose inline cache missed and a `respond_to?` wrote to fill the method cache even when it held the answer, and a block made into a `Proc` wrote to intern its body even when it was interned. Each now reads first under the hold every running heap has (`HandleScope::lookup_method`, `lookup_method_in`, `Classes::cached_lookup`, `Definitions::interned`), and writes only to fill. A safe point took the lock's mutex every turn check once the program had a second Ractor; it is now one load while no heap writes or waits to (`ClassLock::wanted`, kept beside the mutex's state). An `attr_reader` in a Ractor other than the main one read its miss the full way and never filled its site's cache, so every call missed; a name the object holds in its own storage now fills it as the main Ractor's does, and a class's or a module's still reads the full way, under the isolation rules. A heap whose last running thread leaves it for a call made outside the per-Ractor lock lets the class lock go for the call: its one thread around the call (`threads::outside`, `outside_interruptibly`), and of several, the one that leaves the heap to nobody (`threads::release`), the one that takes it back from nobody taking the hold back first; before, a Ractor waiting in `flock` kept every other Ractor's next definition waiting with it. The tables in `spinel-vm/src/shared/` are as they were: the symbol table is append-only behind its `RwLock`, the hash seed and core image are made once, and the signals' counts are the OS handler's and the main Ractor's; the class tables are the `Vm`'s, written under the class lock. Two locks over C library state joined them, since Ractors in parallel could now race it: the environment's (`shared/env.rs`) and, off Linux, the services database's (`shared/services.rs`). `crates/spinel-cli/tests/ractor.rs` runs two more programs against CRuby 4.0.9's output, `parallel` and `outside_lock`; `crates/spinel-vm/tests/shared_tables_stress.rs` interns overlapping names from four threads (under Miri too) and runs three joined heaps defining methods, making blocks and filling caches while the main heap defines methods on the classes they call, and `vm::tests` holds the lock to its rule with several writers and readers under Miri. No ruby/spec delta, since ruby/spec has no Ractor specs: the corpus is unchanged.

**Built so far for shareability (#118):** CRuby 4.0.9's rules for what may be shared, measured. `Ractor.shareable?` is a copy that only shareable objects may make (`heap/copy.rs`, `Options::shareable_only`): every object it reaches must be frozen, but a class or module, an Integer or a Float, `ENV` (#865), and a core class's own state, its `@__name__` instance variables, which stand for CRuby's C struct, except those that hold the program's values (a `Hash`'s pairs and default, a `Struct`'s or `Data`'s values, a `Set`'s items, a `Range`'s ends, an exception's message, a `Method`'s receiver), whose containers are the class's and whose contents are held to it. A `Proc`, and the classes CRuby keeps as `T_DATA` it may not share frozen (`Thread`, `Mutex`, `Queue`, `Enumerator`, `Fiber`, `Binding`, `Random` and the rest `core/ractor.rb` registers), are never shareable, but a `Proc` made shareable, which carries the header's `ractor-shareable` bit. `Ractor.make_shareable` freezes depth first in CRuby's order (`Heap::make_shareable`), so a refusal leaves frozen what came before it, and stops at a `Proc`, which `ractor.rs` checks as `rb_proc_ractor_make_shareable` does — its `self` shareable; no variable outside it written and no `yield` (`ArgumentError`); each one it reads assigned once where it lives and holding a shareable object (`Ractor::IsolationError`) — then gives it an environment of its own holding only those, marks it, and walks again. Whether a local is assigned more than once is the compiler's, as CRuby's `lvar_states` are: when a scope finishes it counts each local's assignments there and in the blocks inside it, a parameter as one, and records the reassigned ones in every block inside (`Iseq::outer_reassigned`). `Ractor.shareable_proc` and `shareable_lambda` copy the block and make the copy shareable with `self:` for its `self`; `copy: true` copies as a message is copied. A shareable `Proc` crosses between Ractors as a copy, as any shareable object does (decision 2a): sent, as an argument, read from a constant, or as a `define_method` body, which another Ractor runs only when it is shareable or the core library's. `crates/spinel-cli/tests/ractor.rs` checks four more programs against 4.0.9's output; no ruby/spec delta, since ruby/spec has no Ractor specs. What is left: `binding` and `eval` inside a shareable `Proc` see its copied environment rather than refusing (`can not access variable 'x' from isolated Proc`); `shareable_lambda(&a_proc)` answers a lambda; a `Symbol#to_proc` `Proc` is refused as not supported; `Proc#dup` does not keep the bit; a frozen `Method` is shareable but sending one is still refused; and a local assigned in code `if false` cuts away counts, where CRuby's compiler drops it first.

## JIT (phase 6)

Bytecode to Cranelift IR, method at a time, after a call count threshold, with inline caches read at compile time and deoptimization back to the interpreter when a guard fails. JIT frames emit stack maps so the precise GC keeps working. ZJIT's design is public reference material for this shape. Not started until the interpreter passes the bulk of ruby/spec, because the JIT can only be as correct as the semantics it copies.

## Native extensions and FFI

**Decision:** `spinel-ext` crate, no CRuby C API.

- Extensions are `cdylib` crates built with `spinel-ext`, exporting `spinel_ext_init`. `require "foo"` looks for `foo.rb`, then `foo.spinel`, then `foo.so`, each across the whole load path, and `require "foo.so"` also finds `foo.spinel` (#39). A `.so` found is a CRuby C extension, refused with a `LoadError` that has no `path`; a `.spinel` found is loaded (#104). The boundary is a versioned `extern "C"` function table with `#[repr(C)]` handles, because Rust's own ABI is not stable across compiler versions; the `spinel-ext` crate is a safe wrapper over that table. A version mismatch is a clean error.
- Values are opaque handles rooted in a `HandleScope`. Extensions never see raw pointers, so the GC is free to move.
- `Spinel::FFI` (default: built on `libffi`) covers the `fiddle`/`ffi` gem use case: load a C library, declare functions, call them.

**Built so far (#103):** the API and the ABI under it. `spinel-ext` depends on nothing, so an extension builds against it alone; `spinel-vm` depends on it for the declarations and implements the host side (`spinel-vm/src/ext.rs`). An extension is a `cdylib` whose crate root says `spinel_ext::extension!(init)`, with `init` a `fn(&mut Context<'_>) -> Result<()>`. The macro exports two symbols. `spinel_ext_header` is a `#[repr(C)]` `Header` — eight magic bytes, the ABI the extension was built against (`spinel_ext::ABI`), the header's size, and the crate's name and version, NUL-padded to 64 bytes each — whose layout is frozen across every ABI, past and future, because it is what a `spinel` reads to decide whether to run anything else. `spinel_ext_init` takes a `RawContext`: a pointer to the host's function table, `Api`, and one to the host's state for the call, which the extension hands back and never reads. `Extension::open` `dlopen`s the library, reads the header a field at a time, and checks it before it looks up the init: an ABI outside `spinel_ext::OLDEST_ABI..=spinel_ext::ABI`, a header without the magic, or no header at all is a `LoadError` (`From` it into an `Error` that raises one) naming the extension, its version and path, the ABI it was built against, the ABI this `spinel` and its version load, and what to do — reinstall the gem so it is rebuilt, or upgrade `spinel` — and none of the extension's code has run. The `Api` table only grows at the end within one ABI; its first two fields, `abi` and `size`, are frozen too, and the extension's init checks them before reading further, answering `Status::ABI_MISMATCH` for a table of another ABI or one shorter than it was built against, which the host reports as a `LoadError` saying to upgrade. 1 is the first ABI; 0, which compiled apps' manifests recorded before, is the ABI before any API, and no `spinel` loads it.

A value crosses as a `RawValue`, an index into the heap's root stack. Each call into an extension — its init, or one call of a method it defined — runs in a `HandleScope` of its own: the receiver and arguments are rooted there, every value the extension makes through the table is too, and they go when the call returns. An index handed back is checked against that scope rather than trusted, so a handle kept from another call or made up is never a read through a stale pointer: one outside this call's range is an `ArgumentError`, and one inside it names a value of this call. The table's v1 entries are `nil`, `boolean`, `integer` (a bignum past the fixnum range), `string` (UTF-8), `kind_of`, `truthy`, `integer_value` (`TypeError` for a non-Integer, `RangeError` past `i64`), `string_bytes` (copied into the extension's buffer, never lent), `const_get`, `define_module`, `define_class`, `define_method` (instance or singleton, with an arity the host checks before calling, -1 for any) and `raise`. A method is a `Native::Ext(index)` into a per-heap table of the extension's function and data pointers; keywords reach it as a trailing Hash, as they reach a C method, and `Method#arity` reports its arity. A failure crosses as `Status::RAISED` with the exception left pending in the host's state, so nothing unwinds across the boundary: the safe wrapper turns an `Err(Error::new("ArgumentError", "..."))` into a raise of the class that path names, `Context::raise` raises an exception class the extension holds, and a Rust panic in a method or init is caught and raised as a `RuntimeError` (`native extension panicked: ...`). A panic in the VM under a table call is caught on the host side and leaves as a `RuntimeError` too. A library `Extension::open` refuses is closed again, so a rebuilt file at the same path is read afresh; one it accepts is never closed, as CRuby never unloads an extension. Not yet: calling back into Ruby from an extension (a native cannot sequence a send; #105's closures do it for C called through `Spinel::FFI`, by suspending the C stack, which an extension's Rust stack could do the same way). The `const_added` and `inherited` hooks a module or class an extension defines owes run once the call into the extension returns — after the init, before `require` answers, or after the method that defined it — in the order they were owed, as frames above the caller's (an init that raises skips them; ponytail in `ext::load`). `require` loads a `.spinel` it finds (#104, below); the first native gem is #105.

The worked example is `spinel-ext`'s crate documentation, which its doctest compiles; the same code is `crates/spinel-vm/tests/fixtures/ext/greeter`, which `tests/ext.rs` builds as a `cdylib` and opens, and also compiles into the test, and checks from Ruby. In short:

```rust
use spinel_ext::{Context, Error, Result, Value};

spinel_ext::extension!(init);

fn init(cx: &mut Context<'_>) -> Result<()> {
    let greeter = cx.define_module("Greeter")?;
    cx.define_singleton_method(greeter, "hello", 1, hello)?;
    Ok(())
}

fn hello<'cx>(cx: &mut Context<'cx>, _self: Value<'cx>, args: &[Value<'cx>]) -> Result<Value<'cx>> {
    let name = cx.to_string(args[0])?;
    if name.is_empty() {
        return Err(Error::new("ArgumentError", "name is empty"));
    }
    Ok(cx.string(&format!("Hello, {name}!")))
}
```

`Greeter.hello("Ruby")` is `"Hello, Ruby!"`, `Greeter.hello("")` raises `ArgumentError: name is empty`, and `Greeter.hello` raises `ArgumentError: wrong number of arguments (given 0, expected 1)`. `tests/fixtures/ext/stale` is an extension whose header says ABI 0 and whose init aborts the process; the test opens it, gets the `LoadError`, and carries on.

**Built so far (#104):** the loader. `require` of a feature that resolves to a `.spinel` — `require "foo"` after no `foo.rb`, or `require "foo.so"` — runs it where a Ruby file would run, through the same steps in `core/load.rb`: it is recorded in `$LOADED_FEATURES` once, under its path, so a second `require` by either name answers false, another thread requiring it waits for the first, and a load that raises is not recorded and runs again on the next `require`. Running it is `Kernel#__load_extension__` (`ext::load`): `Extension::open` and its check, then the init in this heap, then the hooks its definitions owe, so a Ruby `Base.inherited` sees the subclass an extension defines before `require` returns. A library this `spinel` will not load — another ABI, no header, not a shared object at all — is the `LoadError` #103 made of it, before any of its code runs, and an exception the init raises leaves `require` as that exception. A feature deleted from `$LOADED_FEATURES` and required again is opened again and runs its init again, as CRuby's `dln_load` does on the handle `dlopen` hands back; an accepted library is never closed, so every method an extension defined stays callable. A `.so` is still refused as a CRuby C extension. An extension ships in a gem as a precompiled native gem ships its `.so`: built, in the gem's `lib/`, with no `extensions` for the installer to build (package-manager.md, section 6); a compiled app copies it with the gem's other files. `crates/spinel-cli/tests/fixtures/native-gem` is the example gem — a Ruby half over an extension that defines a module, a class, an exception class and methods converting values and raising — and `crates/spinel-cli/tests/native_gem.rs` builds its extension with cargo, installs the gem with `spinel install` from a path, and runs a program using it with `spinel run` and as a compiled app; it also requires an ABI 0 extension and a file that is not a shared object, each a `LoadError` that a `rescue` handles.

**Built so far (#105):** `Spinel::FFI`, and `fiddle` on it. `spinel-vm/src/ffi.rs` is the C half, the `__ffi_*__` primitives: `dlopen`, `dlsym` and `dlclose`, the C heap (`calloc`, `realloc`, `free`), a copy of the bytes at an address and a write of bytes there, `strlen`, a call through libffi — built from the copy the `libffi` crate vendors, so no system libffi is needed — and closures. A value crosses as an 8-byte slot, an integer's bits sign- or zero-extended from its C type or a Float's, and an address as an Integer, signed as `fiddle`'s `PTR2NUM` makes it. No VM value and no address inside the heap ever reaches C: a String argument is a copy on the C heap, written back into the String when the call returns (a frozen one is left alone), and what C does with an address the program gives it is the program's to get right, as in C and in CRuby. `lib/spinel/ffi.rb` is `Spinel::FFI`, the module a program can use directly — `open`, `symbol`, `call`, `closure`, `malloc`, `read`, `write` — converting integers and floats as CRuby's `NUM2INT`, `NUM2ULONG` and `NUM2DBL` do, with their messages. `lib/fiddle/spinel.rb` is `fiddle.so` in Ruby over it, and fiddle 1.1.8's Ruby half is vendored in `stdlib/`; `require "fiddle"` loads the one, which requires the other.

A callback is C asking for Ruby in the middle of a primitive, and the interpreter is not re-entrant. So while any closure is live a call runs on a stack of its own (a `corosensei` coroutine on the same OS thread, so the C library's per-thread state is the caller's). A closure's trampoline suspends that stack and the primitive answers which closure C called and with what; Ruby runs the block as any send runs, and `__ffi_resume__` switches back with its answer. Suspended calls are the heap's (`Heap::ffi`), each resumed only on the OS thread it started on, so callbacks nest, interleave across Ruby threads and survive a Fiber switch. A block that raises, breaks or throws abandons its call: the stack is reset without running anything more on it, which is what CRuby's `longjmp` out of a callback does to the C frames under it. A closure called on a thread that is not running its heap's call ends the process with a message, as CRuby's `rb_thread_call_with_gvl` does when a thread Ruby does not know calls it. A call holds the heap's lock throughout. ponytail: CRuby releases the GVL for a call unless `need_gvl:` says otherwise, so a C call that blocks here blocks the other threads; upgrade by making calls outside the lock, as `threads::outside` makes blocking system calls, re-taking it in a trampoline. `Pointer[string]` copies rather than points into the String, `Pointer#ref` points at a copy of the address, `dlwrap` answers a token rather than an address, and there is no `Fiddle::MemoryView` yet (ponytails in `lib/fiddle/spinel.rb`).

**Built-in gems** (the default gems whose C parts become Spinel primitives, shipped inside the binary at pinned versions): `json`, `digest`, `zlib`, `socket`, `io-console`, `date`, `bigdecimal`, `openssl` (bound to the system's OpenSSL 3 through `openssl-sys`, the `openssl` crate's own bindings, since the crate's safe API cannot copy an HMAC's signing context or name a context's algorithm; large surface, phased), `psych` (libyaml 0.2.5, translated to Rust, behind Psych's API), `etc`, `strscan`, `stringio`, `monitor`, `racc`, `fiddle` (as `Spinel::FFI`), and `ripper` replaced by a Prism-backed shim. Their Ruby halves are the upstream gems' Ruby files. plain data, an Array or Hash of nil, booleans, Integers, finite Floats and valid Strings, is written by a third, `__json_generate__` (#742), an exception made for speed as the parser's was and the owner's decision on #742, and anything else falls back to the Ruby generator. `prism` and `ripper` came with #837: the prism gem's Ruby half is vendored in `stdlib/` at the release of the Prism library Spinel's parser links (so not the copy in Ruby's `lib/`), and its C half is `lib/prism/prism.rb`, the extension's API over Prism's serialization, which the gem's own `Prism::Serialize` reads back (`spinel-parse/src/serialize.rs`, the `__prism_*__` primitives, installed in each heap by `spinel-core` so that the VM never links Prism); `ripper` is `lib/ripper.rb`, Prism's own Ripper translation in the `Ripper` constant, with CRuby's reading of a source. `fiddle` came with #105 (above): the bundled gem's Ruby half vendored in `stdlib/` from the packaged gem, its C half `lib/fiddle/spinel.rb` over `Spinel::FFI`. `openssl` came with #106, phased, its first phase digests, HMAC and random bytes: ruby/openssl's `lib/` is vendored in `stdlib/` (ruby/ruby keeps it in `ext/openssl/lib`), and its C half is `lib/openssl/spinel.rb`, `ossl.c`, `ossl_digest.c`, `ossl_hmac.c` and `ossl_rand.c` in Ruby over the `__openssl_*__` primitives (`spinel-vm/src/openssl.rs`), which make the same OpenSSL calls on the system's OpenSSL 3 through `openssl-sys` and answer a failure as the exception `ossl_raise` builds, message and error queue. A digest's or HMAC's `EVP_MD_CTX` lives in its heap under an id never handed out twice, held by a one-element Array whose finalizer frees it. `openssl.rb` is patched to require `openssl/spinel` in place of `openssl.so` and to skip the Ruby half of each part whose C half is not there yet. Phase 2 (#107) added keys, certificates and TLS: `lib/openssl/spinel/{asn1,bn,pkey,x509,ssl}.rb` over `__openssl_tls__` (`spinel-vm/src/openssl/tls.rs`), its OpenSSL objects in the same per-heap registry. A TLS connection never blocks in OpenSSL: the socket is nonblocking, and Ruby waits on the IO between calls, so other threads run. A callback OpenSSL makes mid-handshake that must run Ruby (certificate verification with CRuby's host name check and `verify_callback`, a server's `servername_cb` and `alpn_select_cb`, a client's `client_cert_cb`) suspends the handshake through OpenSSL 3's retry hooks and runs between calls; one OpenSSL cannot suspend for raises `NotImplementedError` rather than being skipped. `Cipher` and `KDF` are undefined, never stood in for, until their phase. `psych` came with #108: ruby/psych 5.3.1's `lib/` is vendored in `stdlib/` (ruby/ruby keeps it in `ext/psych/lib`), and its C half is `lib/psych/spinel.rb`, `psych_parser.c`, `psych_emitter.c`, `psych_to_ruby.c` and `psych.c` in Ruby over the `__psych_*__` primitives (`spinel-vm/src/psych.rs`). Those drive libyaml 0.2.5, the release CRuby's Psych links, through `unsafe-libyaml-norway`, the maintained fork of a line-for-line translation of libyaml's C to Rust, so events, their marks, syntax errors and emitted bytes are libyaml's: it matched CRuby's Psych on every yaml-test-suite case, where `libyaml-safer`, written after libyaml rather than from it, moved some marks and panicked on one, and `yaml-rust2` keeps no anchor names, version directive or implicit flags. A parse runs over the whole input in one call and answers its events and the error that stopped it, which the Ruby side replays to the handler; when the handler builds objects (a `Psych::TreeBuilder`, as `load`, `safe_load`, `parse` and `parse_stream` use), nesting deeper than 10,000 collections stops it with a `Psych::SyntaxError`, since the interpreter's frames are on the heap and building such a document would recurse until memory ran out (CRuby raises `SystemStackError` a few thousand levels down); event parsing for any other handler is unbounded, as libyaml's is (a `ponytail:` until the interpreter has a recursion limit). Aliases load as the object their anchor made, never expanded, and `load` and `safe_load` refuse them unless given `aliases: true`. An emitter's libyaml state lives in its heap under an id, held as `openssl`'s contexts are, and what libyaml writes goes to the Ruby IO when it flushes. `psych.rb` is patched to require `psych/spinel` in place of `psych.so`. `bigdecimal` came with #109: the bundled gem's Ruby half, bigdecimal 4.0.1's `lib/` from the packaged gem (`power`, `sqrt`, `BigMath.log` and `exp`, `bigdecimal/util`, `math`, `jacobian`, `ludcmp`, `newton`), vendored in `stdlib/`, and its C half `lib/bigdecimal/spinel.rb`, `bigdecimal.c` method for method in Ruby over Integer, with no primitive of its own: a finite value is a sign, an Integer mantissa without trailing zeros and the power of ten it is scaled by, every result is computed exactly and rounded once where the C rounds (VpMidRound's seven modes, the precision limit, `add`/`sub`/`mult`/`div`'s digits, `/`'s default of the operands' precision plus 16, at least 32), and the parse is VpAlloc's, byte for byte. What a program can see of the C's base 10**9 words is counted from where the digits fall against them: the precision `_dump` writes, the digits a Rational is divided out to (`GetCoercePrec`), the word count a NaN or infinity from `/` keeps ("45:Infinity"), how far left `round` reaches before answering zero in modes other than ceiling and floor, a zero's stale exponent that makes `to_i` answer `(0/1)`, and precision counts that wrap past 2**63. `BigDecimal(float, n)` runs Ruby's dtoa's mode 2 step for step in the same double arithmetic, which rounds some halves up from its floating-point estimate (`BigDecimal(2.675, 3)` is 0.268e1). The exception mode, rounding mode and limit are the thread's, under the `Thread#[]` keys CRuby uses. `bigdecimal.rb` is patched to require `bigdecimal/spinel` in place of `bigdecimal.so`. `zlib` came with #59: the gem has no Ruby half, so `lib/zlib.rb` is `zlib.c` in Ruby, and what Ruby cannot say is libz itself, zlib 1.3.1's deflate, inflate and checksums ported to Rust (`spinel-vm/src/zlib.rs`, behind `__zlib_run__` and three more), a port rather than a crate because a program sees libz's bytes. A stream's state lives in a BINARY String the heap owns, read and rewritten in place. Lockfiles that pin these resolve to the built-in copies (package-manager.md, section 6).

**Spinel-native gems** for popular third-party C extensions, published to rubygems.org under their own name, `<gem>-spinel` with standard platforms, so that stock Bundler never picks one in place of `<gem>`, and substituted for the locked gem at install time (package-manager.md, section 6): `pg` on the system's libpq, as upstream's source gem links it (#114: `gems/pg-spinel`), `sqlite3` on the SQLite amalgamation upstream bundles (libsqlite3-sys's, #113: `gems/sqlite3-spinel`), `nio4r` on the system's epoll or kqueue, the calls libev makes for upstream (#115: `gems/nio4r-spinel`), `puma` on its own HTTP parser's state machine, the tables Ragel makes of upstream's grammar, and the system's OpenSSL 3 for MiniSSL (#116: `gems/puma-spinel`), `bcrypt`, `msgpack`. Each presents the upstream gem's Ruby API. `nokogiri` is the hard one and is out of scope until phase 7.

## Conformance

- `spec/ruby` is a git submodule of ruby/spec and `spec/mspec` of ruby/mspec, and mspec runs on Spinel itself ([#145](https://github.com/ar4mirez/spinel/issues/145)). Until then `spec/harness/`, a Rust runner that read each spec file's syntax tree and ran the examples it could, stood in for it; it is gone. `spec/spinel.mspec` and `spec/spinel/runner.rb` keep its three outcomes: an example *passes*, *fails* — an expectation was not met — or is *blocked*, because Spinel refused something it cannot do yet or the example raised anything but an unmet expectation. Every example, hook and file load runs inside a refusal boundary (`__refusal_boundary__`, with a per-example instruction budget), so a refusal ends the example rather than the process, through every `ensure` and past every `rescue`. The `blocked` column shrinks slice by slice. `scripts/spec.sh [path]` runs the corpus as a set of parallel mspec processes and merges their records (`scripts/spec-report.sh`); each run ends by ranking what blocked examples, in order of how many each accounts for, which is how the next slice gets chosen from data rather than from a guess about which corner of Ruby matters. `scripts/verify-passes.rb` runs every example Spinel passes again, under the same mspec, on a real Ruby.
- CI publishes `bench/spec-status.md`: pass/fail/skip counts per directory. That table is the project's progress bar.
- Skips live in `spec/tags/` with a reason. There are no expected-failure markers in code. The format is mspec's own — `fails(reason):full description`, in `spec/tags/<path>_tags.txt` mirroring `spec/ruby/<path>_spec.rb` — so mspec reads them as it reads anyone's ([#145](https://github.com/ar4mirez/spinel/issues/145)). What is Spinel's and not mspec's is that the reason is required, that only `fails` is honoured, and that a tag naming an example which no longer exists fails the run. A tagged example is reported `skipped`, never `passed`. See `spec/tags/README.md`.

## Regex

**Decision:** Spinel's own engine, `crates/spinel-regex`: a parser for Ruby's
dialect and a backtracking matcher, in Rust, with no dependencies.

Ruby's regexes are Onigmo's, which is neither PCRE nor Rust's `regex`. The
decision was measured rather than argued. `scripts/regexp-oracle.rb` takes every
regexp literal `ruby/spec`'s `language/regexp/` actually uses, runs each against
a thirty-subject probe corpus on a real CRuby, and writes the answers to
`crates/spinel-regex/tests/oracle.txt`. `crates/spinel-regex/tests/oracle.rs`
replays the table through the engine on every `cargo test`, so the dialect is
checked against Ruby continuously rather than at the moment somebody read a
reference page.

**Rejected: `fancy-regex`.** The obvious lazy answer, and the measurement is
what ruled it out. Of 338 patterns CRuby accepts, replayed through `fancy-regex`
with `(?m)` prepended — the fairest translation available, since Ruby's `^` and
`$` are always line anchors — 281 agreed, 16 were rejected, and **41 gave a
different answer**. Some of the 41 are reachable by a translation layer:

| | Ruby | Rust's `regex` |
|---|---|---|
| `\w` `\d` `\s` | ASCII | Unicode |
| `[[:alpha:]]` | Unicode | ASCII |
| `/m` | dot matches newline | `^`/`$` match at line breaks |

The rest are properties of the match engine and no wrapper reaches them:
`/(a*)*/` against `"a"` leaves group 1 empty in Ruby and full in `fancy-regex`;
`/(a|\2b|())*/` against `"ab"` matches two characters in Ruby and one in
`fancy-regex`. A backend that silently answers differently for one pattern in
eight is exactly the plausible-but-wrong answer this engine refuses, and closing
the gap would need a list of patterns known to be wrong — which the conformance
rule forbids.

**Rejected: binding Onigmo.** It is the reference implementation, it is an
independent library rather than CRuby lineage, and it would be correct on the
whole dialect from the first commit. It also puts a C toolchain in every build,
which costs the cross-compilation story and `spinel build --compile`'s
single-static-binary promise, and it needs a wrapper across the GC and encoding
boundary that is itself a source of divergence. The `spinel-regex` boundary is
narrow — compile a pattern, match at an offset, read capture offsets — so Onigmo
stays available as a drop-in if the remaining dialect proves more expensive than
the toolchain.

What the engine does not implement yet returns `Error::Unsupported`, which the
VM turns into `Error::Unknowable` and the spec runner reports as *blocked*: never a
pass, never a wrong answer. Today that is a level in a conditional's group,
`(?(<1+1>)...)`, and the six scripts
(`\p{Hiragana}` and the rest) an EUC-JP or Shift_JIS pattern names in its own
codes.

A group any `\g<>` calls is a subroutine, run by a call where it is written
and at every call, as Onigmo compiles it: so a call may recurse, and
`\k<name+n>` can read the capture `n` call levels away from an `Event`
history of the path's calls, returns and captures — which is also how a
recursive group's end finds the start it pairs with. A call that can reach
itself before matching a character is Onigmo's `never ending recursion`.
`(?~absent)` is `OP_ABSENT` step for step, and `\X` is UAX #29's rules over
the `Grapheme_Cluster_Break`, `InCB` and `Extended_Pictographic` sets in
`tests/properties.txt`.

A quantifier on a quantifier — `(?:a?)+`, `a**`, and `a{0,1}+`, since only
`?+`, `*+` and `++` are possessive — is reduced to the one it means by
Onigmo's `ReduceTypeTable`, as measured for all 36 pairs, and its warning is
kept on the compiled pattern for the caller to say. CRuby compiles a regexp
literal as it parses it, so `spinel-parse` checks each literal with
`spinel_regex::check`: one that is not a pattern is a `SyntaxError` before
anything runs, and its warnings are said once, with the parser's. A literal
the parser leaves to the run time — in a file whose magic comment is not
UTF-8, with an encoding of its own, or whose bytes are not UTF-8 — says them
on its first compile instead, and the parser records on each literal which it
was. A constructor says them at its call, except `Regexp.new(regexp)`, whose
pattern already did.

A match runs under a step budget, five million steps and 64 more for each
byte of the subject, so that a match walking a long subject once is answered
while backtracking built to blow up still is not, and refuses with
`Error::Budget` past it, unless its caller gives it a deadline: `Regexp.timeout` or a pattern's own
`timeout:`. Then the deadline replaces the budget, as CRuby gives up only when
its timeout runs out, and a match past it is `Regexp::TimeoutError`.

`\p{}` in a UTF-8 pattern reads `tests/properties.txt`: every name CRuby's
Onigmo takes there (general categories, scripts, binary properties, blocks
and ages), measured over every codepoint by `scripts/regexp-oracle.rb` as the
POSIX brackets are, and baked into range tables by `build.rs`. An age is
stored as what its version added, and `\p{Age=V}` is the union up to `V`. In
any other encoding `\p{}` takes only the POSIX bracket names.

Under `/i` a UTF-8 subject folds by Unicode's full case folding, measured
into `tests/casefold.txt` (#788), so `ß` matches `ss` and `ﬃ` matches `ffi`.
Onigmo gets there by rewriting each string the pattern spells into the ways
it may be spelled, until there are more than eight alternatives, and
comparing the rest folded (`regcomp.c`'s `expand_case_fold_string`); a class
adds the strings its characters fold to, `s{2}` is the string `ss`, and a
look-behind expands nothing. `src/fold.rs` is that rewrite, and
`tests/folds.txt` measures it against subjects of its own. Every other
encoding folds one character to one.

The engine follows Onigmo's matcher here, not its search, and the two
disagree in CRuby itself:

- The search picks the starts it tries from a first-byte map built with the
  multi-character folds turned off, so `/(?i)S{2,3}/` finds `"ẞ"` and
  `/(?i)(?:x|S{2,3})/` does not. Spinel finds both.
- A look-behind whose folded body takes more or fewer characters than Onigmo
  counted lets CRuby carry on from wherever the body ended, and what it then
  finds depends on the search. Spinel steps back as far as Onigmo counts and
  asks a positive body to end at the look-behind; a negative one forbids any
  match of its body. Every measured case agrees.
- CRuby compiles a pattern of ASCII alone for US-ASCII against a subject of
  ASCII alone, and US-ASCII folds nothing past one character to one, but it
  keeps a UTF-8 recompilation once a subject past ASCII asked for one: the
  same `Regexp` answers `"ss"` differently depending on what it matched
  before. The VM reads that pair as BINARY, CRuby's first answer, and
  `tests/folds.txt` compiles every pattern for UTF-8 to stay deterministic.

None of these is in the oracle tables.

Matching is byte-oriented and reports byte offsets; `MatchData` converts to
characters, because that is what `#begin` answers. A match reads its subject
in one of five ways, `spinel_regex::Encoding`: as UTF-8; a character per byte
with only ASCII's classes and cases, which is BINARY and US-ASCII, and the
code pages Onigmo classes nothing past ASCII in (IBM437, macRoman,
Windows-1258 and the rest); a character per byte with the encoding's own
table, which is ISO-8859-1 to -16, KOI8-R and -U and Windows-1250 to -1257 —
`Single(Charset)`, a `Charset` per distinct table, so Windows-1256 reads as
ISO-8859-6; or a multibyte character at a time, which is EUC-JP,
Shift_JIS with Windows-31J, Big5, CP949, EUC-KR, GBK, GB18030, EUC-TW and
Emacs-Mule, and the variants that measure the same as one of them (UTF8-MAC
reads as UTF-8, eucJP-ms as EUC-JP, CP950 as Big5, GB2312 as EUC-KR, …).
A single-byte table has Onigmo's classes and two
case maps, neither Unicode's: a literal's, which is not symmetric (Windows-1251's
`/\x80/i` matches `"\x90"`, not the other way) and reaches into ASCII
(ISO-8859-9's `/i/i` matches `İ`), and a class's, which is smaller. A class of
one character is compiled as that character, as Onigmo does, and a
backreference takes the literal map either way round. All of it is measured
by `scripts/regexp-oracle.rb` into `tests/encodings.txt` and generated into
`src/single_byte.rs`. The
machine compares `char`s, so a multibyte character is carried at a private-use
codepoint numbered by Onigmo's own code for it — its bytes read as one
big-endian number — which keeps ranges in order without the Unicode mapping
those encodings need a table for; it is word, graph and print and nothing
else, and folds case only by the encoding's arithmetic, which only EUC-JP and
Shift_JIS have. GB18030, EUC-TW and Emacs-Mule have codes of three and four
bytes too many for those planes, so theirs are carried by rank: every
character past ASCII in code order, from `U+0080` up past the surrogates.
GB18030's four bytes spell 1.6 million codes, more than there are scalar
values, but the ones a character is assigned and its two-byte codes are
exactly as many as the scalar values past ASCII; a pattern or subject with
any other four-byte code is refused. Shift_JIS's, Big5's, CP949's, GBK's
and GB18030's trail bytes overlap ASCII, so stepping back means reading
forward from a byte that can only start a character, and a substring search
skips a match that starts inside one, as CRuby's does. The characters'
boundaries, as an automaton per encoding, and their classes and both folds
are measured into `crates/spinel-regex/tests/encodings.txt` and replayed by a
unit test. A
`Regexp` carries its own encoding as CRuby does, in its source String: `/u`,
`/e` and `/s` fix it to UTF-8, EUC-JP and Windows-31J, `/n` makes it BINARY
when the source names a byte past ASCII (a raw one only from a BINARY String;
any other is a `RegexpError`, as in CRuby), and an ASCII pattern is US-ASCII and
free to match in the subject's encoding. Which encoding a match uses, and when
the two cannot meet, is `rb_reg_prepare_enc`'s decision, ported. The program
does not depend on the encoding, so one compiled pattern serves every subject;
only the source is parsed in its own: a `\xff` is a byte in BINARY and the
other single-byte encodings, and in the multibyte ones it leads a character
the escapes after it finish. A source or subject past ASCII in CESU-8 is
refused until the engine reads its characters
([#388](https://github.com/ar4mirez/spinel/issues/388)). A pattern written in
UTF-16 or UTF-32 is in that encoding, fixed, and compiled from the characters
it spells; matching one against a subject in its encoding is refused until the
engine reads those subjects, and against any other is CRuby's
`Encoding::CompatibilityError`. `$~` is one slot
per heap — Ruby scopes it per frame and per thread, which arrives with the
frame specials and with Ractors. The refs derived from it — `$1`, `$&`,
`` $` ``, `$'`, `$+` — are read off that match rather than out of the global
table, which is why `defined?($&)` is nil until something has matched while
`defined?($~)` never is.

A literal whose source is known at compile time is an `Iseq` literal, and two
evaluations of one are the same object. An interpolated literal cannot be:
literals are immutable and shared across Ractors, and this one is not known
until the frame runs. So the source is concatenated at run time and compiled
from the result, giving a fresh frozen `Regexp` each time — which is what Ruby
does, measured. `/o` is the exception: it interpolates once and caches the
*object* per literal site, so a method holding one answers the same `Regexp` on
every call. That cache is per heap, keyed by the body and the site's index
within it, and holds an `Arc` of the body so the address it is keyed by cannot
be reused.

## Open questions to settle when their slice arrives

What it still refuses is CESU-8, UTF8-MAC and the carrier variants.
- **Generational GC timing.** Only after allocation profiles from real gems exist.
