# PRD 0012 — Exceptions, `ensure`, `retry`, `throw`/`catch`, non-local `break`/`return`

Tracks [#12](https://github.com/ar4mirez/spinel/issues/12). Milestone: Phase 1: a VM that
runs `language/`. `P0`, `size:L`, `area:engine`.

## Objective

Every slice so far could only ever *stop*. `interp::eval_in` returns
`Result<Value, Error>`, and `Error::Raise` — the variant that means "Ruby would raise
here" — has always escaped to the caller, because there was nothing in between that could
catch it. Ruby programs are not written that way: a raise is a value that travels, an
`ensure` is a promise that runs whatever happens, and `break` out of a block is the same
mechanism wearing a different hat.

This slice makes control flow *non-local*. After it, an exception is an object with a
class and a message, `rescue` chooses handlers by class, `ensure` runs on every exit path
including the ones that are not exceptions at all, and `retry`, `throw`/`catch`, and
non-local `break`/`return`/`next`/`redo` are all the same unwinder with different
targets.

### The honest shape of the target

The issue's definition of done names seven spec files. Measured at the baseline below,
four of them are gated on something that is not exceptions at all:

```
rescue_spec.rb   60 examples · 0 passed · 60 blocked   ← 60/60 on `ScratchPad`
next_spec.rb     35 examples · 0 passed · 35 blocked   ← 28/35 on `ScratchPad`
break_spec.rb    39 examples · 2 passed · 37 blocked   ← 29/37 on `ScratchPad`
return_spec.rb   43 examples · 4 passed · 39 blocked   ← 13/39 on `ScratchPad`, 16 on ivars
```

`ScratchPad` is mspec's own recorder — `ScratchPad.record []`, `ScratchPad << :x`,
`ScratchPad.recorded` — and it appears in a `before :each` hook that the harness prepends
to *every* example in `rescue_spec.rb`. No amount of exception machinery moves that file
off zero while the recorder is a `NameError`. So the recorder is in scope, and R10 says
what it costs.

What is **not** reachable and is not pretended to be: instance variables
([#151](https://github.com/ar4mirez/spinel/issues/151)) block 16 of `return_spec.rb` and
11 of `ensure_spec.rb`; splats and multiple assignment
([#154](https://github.com/ar4mirez/spinel/issues/154)) block 10 more; a growable `Array`
([#15](https://github.com/ar4mirez/spinel/issues/15)) is what `ScratchPad <<` would want
and R10 explains why it does not get one.

The measurable claim is therefore: **unwinding stops being the blocker.** After this
lands, no example in the corpus is blocked on `` `begin`/`rescue` ``, `` `break` out of a
block ``, `` `return` from a block ``, `` `next` outside a loop or block ``, `` `redo` ``,
`catch`, or `throw`; `should raise_error` becomes a matcher the harness can *check*
rather than a reason to block; and the `blocked → passed` delta is stated in the PR with
every remaining reason named and attributed to a later slice.

## Non-goals

- **Instance variables.** Still [#151](https://github.com/ar4mirez/spinel/issues/151).
  `rescue => @e` stays `Unsupported`. Named in the numbers, not smuggled in.
- **A growable `Array`.** [#15](https://github.com/ar4mirez/spinel/issues/15)'s. R10 gets
  `ScratchPad <<` from `Array#+`, which allocates, rather than from a mutator that would
  be a second array representation #15 has to delete.
- **Backtraces.** `Exception#backtrace` answers `nil`. A real one needs frame source
  positions the compiler does not record yet, and `caller_locations` is phase 2's.
  Answering `[]` would be a plausible-but-wrong answer of exactly the kind
  `Error::Unknowable` exists to refuse.
- **`Exception` reflection beyond `message`/`to_s`/`full_message`.** `#cause`, `#=~`,
  `#exception`, `Exception.exception`, custom `#initialize`, `retry` limits — phase 2's
  `core/exception/`.
- **`rescue` on a splatted class list** (`rescue *classes`) and **`rescue` into anything
  but a local**, which need #154's splat and #151's ivars respectively.
- **`SystemExit`, `Signal`, `at_exit`.** Phase 3's process model.
- **`ensure` interacting with fibers.** Phase 2.

## Users

The compiler, the interpreter, and `spec/harness`. Also `defined?`, which
[#13](https://github.com/ar4mirez/spinel/issues/13) left reporting *blocked* where Ruby
swallows an exception and answers `nil`: R8 pays that debt.

## Requirements

- **R1 — the exception hierarchy is measured, not typed.** `Exception` is currently the
  only builtin. The classes `rescue` selects on are bootstrapped from a table generated by
  `scripts/exceptions-oracle.rb` reading CRuby's own `ObjectSpace`, and a Rust test
  re-checks the bootstrap against it. Nothing about the hierarchy is written by hand.
- **R2 — an exception is an object.** Allocated with `Payload::Slots`, slot 0 the message
  and slot 1 the backtrace (always `nil`, see non-goals). `Exception#message`, `#to_s`,
  and `#full_message` are natives; `#backtrace` answers `nil`.
- **R3 — every existing `Error::Raise` becomes a real raise.** The variant already carries
  the class name and Ruby's own message text, asserted since #11 and #13. Turning it into
  an object is one function, and every site that emits it starts being catchable at once.
  `Error::NoDispatch`, `Error::Budget`, and `Error::Unknowable` are *not* Ruby semantics
  and must keep escaping past `rescue` untouched, or the harness would report a construct
  the VM cannot compile as an exception a spec caught.
- **R4 — catch tables, per bytecode range.** `Iseq` grows a `catch_table: Vec<CatchEntry>`
  of `[start, end)` instruction ranges with a handler target and the operand-stack depth
  to restore. Indices are absolute *within the `Iseq`*, which keeps position independence:
  the table moves with the code it describes and needs no relocation, exactly as the
  relative-jump rule does for instructions.
- **R5 — `ensure` runs on every exit path, and is compiled once.** The normal path enters
  the ensure body through the same door the unwinder does: `EnterEnsure` parks the pending
  reason (a value, or an unwind in flight) on the frame, the body runs, and `LeaveEnsure`
  either restores the value or resumes the unwind. One copy of the body, so an `ensure`
  containing its own `return` or `break` cannot behave differently depending on which path
  reached it. YARV compiles the body twice; this does not, and R11 is the test that says
  the difference is not observable.
- **R6 — `retry` re-runs the protected body.** A same-frame backward jump to the region
  start with the operand stack truncated to the region's base. Legal only inside a
  `rescue` clause; anywhere else is a `SyntaxError` at compile time, as in Ruby.
- **R7 — non-local exits target a *frame*, not a depth.** Each `Call` carries a unique
  `id`. A `Proc` records two of them: the frame its `break` ends (the call the block was
  passed to) and the method frame its `return` leaves. Unwinding searches for that id; if
  it is not on the frame stack the call has already returned, and Ruby's answer is
  `LocalJumpError`, which is what is raised.
- **R8 — `defined?` swallows.** With an unwinder, `defined?(recv.m)` catches anything
  raised while evaluating the receiver and answers `nil`, as Ruby does. #13 named this
  and left it blocked.
- **R9 — `throw`/`catch` are `Kernel` natives.** `catch` runs a block under a tag,
  `throw` unwinds to the matching one by object identity, and an unmatched tag raises
  `UncaughtThrowError` with Ruby's own message. `ensure` blocks between the two run.
- **R10 — the harness gets `ScratchPad`, and it is built from generic primitives.**
  `Native::Getter(slot)` and `Native::Setter(slot)` — what `attr_accessor` compiles to
  when `core/*.rb` asks — plus `Array#+`, which is pure. `ScratchPad` is then an ordinary
  object the harness binds to a constant, and `<<` is Ruby: `record(recorded + [value])`.
  Copy-on-append is not `Array#<<`'s semantics, and the difference is observable by
  aliasing `recorded` — so R12's oracle re-runs every claimed pass against a real
  `ScratchPad` on CRuby, where an aliasing example fails loudly rather than passing here.
- **R11 — the harness can *check* `should raise_error`.** The 100 examples blocked on
  `undefined method 'should' for an instance of Proc` are `-> { }.should raise_error(C)`
  and `-> { }.should_not raise_error`. The harness recognises that shape the same way it
  already recognises `.should ==`, runs the proc, and compares the raised class against
  the expected one. Until now `Error::Raise` was reported *blocked*, which the issue's own
  triage note flags as quietly hiding real failures; after this it is a first-class
  outcome and a wrong exception class is a **failure**, not a block.
- **R12 — the oracle tracks the harness.** `scripts/verify-passes.rb` re-runs every
  claimed pass on CRuby. It gains the same `raise_error` matcher and the real mspec
  `ScratchPad`, because a harness that grows a matcher the oracle does not have is a
  harness whose new passes nobody checks.

## What the audit caught

Five real bugs, four of them older than this slice. Every one was invisible until
`should.raise` became something the harness could *check* — which is the argument
for R11 stated as a result rather than as a plan.

1. **Methods were not arity-checked at all** (#11). `bind` took a `lambda: bool` that
   meant two things at once — "spreads a lone `Array`" and "insists on the count" —
   and a method was passed `false` for both, so `def foo(a, b); end; foo(1)` answered
   `nil` instead of raising `ArgumentError`. It is now a `Binding` enum whose two
   values name the two rules together, because the reason the `bool` was wrong is
   that its name described one rule and was read as the other. Five `def_spec.rb`
   examples went from *failing* to passing.
2. **A `rescue` swallowed "this method is not implemented yet."** `Error::Raise
   { class: "NoMethodError" }` was indistinguishable from Ruby's own `NoMethodError`,
   so `core/array/reject_spec.rb`'s `begin; a.reject! { ... }; rescue StandardError; end`
   caught Spinel's *gap* and carried on down a branch Ruby never takes, then failed a
   comparison for a reason unrelated to the behaviour under test. It is now
   `Error::NoSuchMethod`, which no `rescue` can catch — restoring the property that
   held before this slice only because nothing could catch anything.
3. **`defined?` did not look through parentheses** (#13). `defined?((a))` answered
   `"expression"` where Ruby says `"local-variable"`, and `defined?((a, b = 1, 2))`
   answered `"expression"` where Ruby says `"assignment"`. A wrong answer, not a
   missing one.
4. **`BasicObject.new("x")` was silently accepted.** No `initialize` anywhere means
   `BasicObject#initialize`, which takes none.
5. **`lambda(&a_proc)` quietly made a lambda**, which Ruby has refused since 3.0 —
   because the conversion silently changes what `return` inside that proc means.

Three places now *refuse* where they used to answer, each for the same reason: the
answer Spinel would give is indistinguishable from a wrong one.

- `new` on an exception class whose CRuby `initialize` is its own — `SignalException`,
  `KeyError`, and nine others, **measured** by the oracle rather than judged. Spinel
  implements `Exception#initialize` and would otherwise report success for arguments
  it never validated.
- A block parameter list spreading an object that defines `#to_ary`. Ruby calls it;
  the binder is on the Rust stack and cannot. Binding `a` to the object and `b` to
  `nil` would also hide a `#to_ary` that raises, which `block_spec.rb` asserts on.
- A singleton `def` on a receiver that defines `singleton_method_added`. The hook is
  #28's; defining the method without firing it reports a state the program never
  reached.

Two debts paid that were not in the plan, both because `ScratchPad` needed them and
both flagged in the code as owed:

- **The send behind `BinOp`'s fast path.** `bytecode.rs` has said since #10 that an
  operand the fast path does not cover should become an ordinary send and that #11's
  calling convention was what it waited for. #11 landed; nothing wired it up. Now
  `Array#+` and every user-defined operator work.
- **`spec/harness` reporting `Error::Raise` as blocked.** The issue's own triage note
  warned this "will keep quietly hiding real failures". A wrong exception class inside
  `should.raise` is now a failure. It is not fully paid: an uncaught exception in an
  ordinary statement is *still* reported blocked, because
  `NameError: uninitialized constant ModuleSpecs` is a fixture this harness cannot
  `require` far more often than it is a disagreement. R12's oracle is what keeps that
  conservatism from hiding anything.
