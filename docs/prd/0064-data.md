# PRD 0064 — `Data`

Follows [#30](https://github.com/ar4mirez/spinel/issues/30) (PRD 0063) ·
Phase 2 · `area:core-lib`

## Objective

`Data`, Ruby 3.2's immutable value class, did not exist: all 88 of
`core/data`'s examples were blocked. It is `Struct`'s sibling and was left
out of that slice only to keep the slice one class.

## Baseline

Corpus 16678 passed, 0 failed, after PRD 0063. `core/data` 0 of 88.

## Design

**It is Ruby.** `core/data.rb`, with no new primitive. Values are a Hash in a
hidden instance variable; members are an Array on the class, found up the
ancestor chain as a struct's are.

**Two steps, and a subclass may stand between them.** `new` turns positional
arguments into keywords. `initialize` takes keywords only, checks that every
member is there and nothing else is, and freezes. So a class that writes its
own `initialize(width:, height:)` and calls `super` with a third, computed
member works whichever way its caller wrote the arguments.

**`with` goes through `initialize`** for the same reason: a class with its
own sees the replaced values. With no arguments it is the object itself.

**Keys may be Strings**, or what converts with `to_str`, in `new`, `with` and
`deconstruct_keys`. Anything else is a TypeError.

**`Data.new` does not exist.** It is undefined on `Data` itself, and each
defined class gets its own.

**Shared with `Struct`:** the recursion guard and the class's real name. An
anonymous `Data` that contains itself is named in the inner occurrence —
`#<data #<Class:0x…>:...>` — though not in the outer one. Measured.

## Came with it

- `Struct#inspect` and `Data#inspect` for an anonymous class with no members
  are `#<struct >` and `#<data >`, space kept. Measured; PRD 0063 had trimmed
  it.

## Not done

- Two `core/data` examples stay blocked: their expected TypeError message is
  ruby 4.1's wording, and this prints 4.0's.
- `Kernel#Float` does not exist, which a `Data` with a converting
  `initialize` commonly wants. Found measuring; not this slice.
- A `FrozenError` from the VM names the class and not the object's `inspect`.
