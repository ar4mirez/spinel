# PRD 0065 — `Time`

Issue: [#32](https://github.com/ar4mirez/spinel/issues/32) · Phase 2 ·
`area:core-lib`

## Objective

`Time` could say what time it was and subtract two of itself, which is what
mspec's timer needed (#145). Everything else — calendars, zones, formatting —
was undefined, and 632 of `core/time`'s 650 examples were blocked.

## Baseline

Corpus 16764 passed, 0 failed, after PRD 0064. `core/time` 16 of 650.

## Design

**An instant is two Integers**: seconds since 1970 UTC, and nanoseconds into
that second. Every field a Time answers is arithmetic on those and a UTC
offset, and all of it is Ruby in `core/time.rb`. The only primitive is the
clock read, which was there already — the issue's second condition.

**Three ways of reading one.** `:utc`; `:fixed`, an offset the program gave
and no zone name; `:local`, whatever the system's zone was at that instant.
`utc`, `localtime` and `getlocal` move between them without touching the
instant.

**The calendar is the era arithmetic** — days since the epoch to a civil date
and back with no table — so it is exact for any year, negative ones included.
A day past the month's end, an hour of 24 and a second of 60 run on into what
follows, as Ruby's do.

**The local zone is read from the files the C library reads**, in Ruby.
`Time::Zone` (private) takes `TZ`, or /etc/localtime when it is unset. A name
under the zone directory is a TZif file: a table of instants at which the
offset changed, then a POSIX rule for everything after the table. The files
systems ship now end their table in 2007 and leave the rest to the rule, so
the rule is evaluated — `M3.2.0,M11.1.0` and the `J` and plain-day forms — and
the same code reads a `TZ` that *is* a rule, such as `CET-1` or
`EST5EDT,M3.2.0,M11.1.0`. No libc call, and so no dependence on whether `ENV`
writes reach the process environment.

**A local reading that happens twice** when clocks go back is the later one,
unless the ten-argument form says which; **one that never happens** when they
go forward is taken as if they had not. Measured against CRuby in New York.

**A zone is fixed when the Time is made.** `Time.local` and `localtime` read
the zone then, not when the Time is next asked, so a Time made under one `TZ`
keeps it. A frozen Time is asked afresh rather than written to.

**A zone may be an object** with `local_to_utc` and `utc_to_local`. It is
shown the reading as a UTC Time; what `utc_to_local` answers is read by its
clock face, and what `local_to_utc` answers by its instant. `abbr` feeds `%Z`,
`dst?` feeds `isdst`, and a Time subclass with `find_timezone` has names
looked up through it.

**`strftime`** is a small interpreter: flags, width, colons, letter. Of `_`
and `0` the later decides the padding; `-` drops it; `^` and `#` change case;
`%-z` on a UTC time is RFC 3339's `-0000`.

**A Float is split exactly.** It is an integer times a power of two, and the
nanoseconds are that product floored. Float arithmetic rounds `-1.3 + 2` to
0.7 and loses the nanosecond: `(Time.at(100) + -1.3).usec` is 699999.

## Not done

- **Nanoseconds are the finest grain.** Ruby keeps a Rational, so
  `Time.at(0.1)` there remembers the float's whole expansion. `Rational` does
  not exist here; `subsec`, `to_r` and about 80 examples wait for it.
- `Marshal` (`_dump`, `_load`), 11 examples.
- A `TZ` that is neither a file nor a rule is UTC under no name.
- Leap seconds in a zone file are skipped over, not applied.
- `Time.new(string)` reads the ISO-like form only, and reports a malformed
  one with fewer distinct messages than CRuby.

## Check

Rows in `crates/spinel-vm/tests/eval.txt`, measured on ruby 4.0.6. None of
them reads the local zone, which differs by machine; the zone code is checked
by `core/time`'s own examples, which set `TZ`. The ruby/spec delta is in the
pull request.
