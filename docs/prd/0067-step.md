# PRD 0067 — `step`, and the sequence it answers

Follows PRD 0066 · Phase 2 · `area:core-lib`

## Objective

`Numeric#step` did not exist for any class, and neither did `Range#step`,
`Range#%` or `Enumerator::ArithmeticSequence`, which all three answer without
a block. 143 examples in `core/numeric` stopped at the first.

## Baseline

Corpus 17735 passed, 0 failed, after PRD 0066.

## Design

**One walk, used four ways.** `core/arithmetic_sequence.rb` has the walk —
first term, last, distance, whether the last is excluded — and
`Numeric#step`, `Range#step`, `Range#%` and the sequence's own `each` all
call it. No primitive.

**Exact numbers are stepped by adding; Floats are not.** Adding 0.1 ten
times does not arrive at 1.0. When any of the three is a Float the number of
terms is worked out first, with the allowance for rounding CRuby's
`ruby_float_step_size` makes, and each term is `begin + i * step`, the last
clamped to the end. An infinite distance in the direction of travel never
ends; infinity to itself never starts; an infinite step yields the first term
once.

**`Enumerator::ArithmeticSequence` is a value**: `begin`, `end`, `step`,
`exclude_end?`, `first`, `last`, `size`, `==`, `hash`, and an `inspect` that
is the call that would make it again — `(1.step(by: 2, to: 7))`,
`((1..10).%(3))` — for which it remembers how it was made. It is an
Enumerator over itself, so `with_index`, `lazy` and the rest come from there.

**`Numeric#step` takes its arguments either way**, `1.step(10, 3)` or
`1.step(by: 3, to: 10)`, and says so when one is given twice. A step that is
not a number makes an ordinary Enumerator without a block, and with one is
asked for its sign, which is where it says it is not a number.

**`Range#step` has three cases.** A numeric range is a sequence. A String
range counts along `each`. Anything else is stepped by `+`, in the direction
the range runs, with one addition first to see that the step runs the same
way — CRuby's `range_step`.

## Not done

- `ArithmeticSequence#last` builds the whole sequence to find its end.
- The `Complex` side of `Numeric` (`rect`, `polar`, `arg`, `i`, `to_c`) is
  what still blocks most of the rest of `core/numeric`.
