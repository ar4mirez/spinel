# Test runner

Goal: `spinel test` runs a project's Minitest or RSpec suite in parallel with no configuration, and `spinel test --watch` reruns affected files on save.

## Scope

Spinel schedules, parallelizes, and reports. Minitest and RSpec still define what a test is and what passes. No new assertion library, no new DSL. Prerequisite: both frameworks run on Spinel's VM (phase 3 milestone).

## Discovery

- `test/**/*_test.rb` → Minitest. `spec/**/*_spec.rb` → RSpec. Both present: run both.
- Built (#94): `spinel test FILE[:LINE]...` runs the files given instead, a file ending `_spec.rb` through RSpec and any other through Minitest. `spinel test path/to/file_test.rb:42` runs one test by line: the worker resolves it once it has loaded the file. Minitest: the test method that starts nearest at or above the line, by each test method's `source_location`, which, unlike the syntax tree, also finds a `test "..." do` block and a `define_method`; only the classes that file defined are filtered, through `runnable_methods`, so other files given whole still run whole. RSpec: `file:line` is passed through to RSpec's own location filter (`filter_manager.add_location`, as `rspec file:line` adds it), which picks the example or group declared nearest at or above the line; passing it to `RSpec::Core::Runner.run` instead would `load` the file a second time. A path that is not a file, a directory included, or a file given more than once exits 1 before anything runs.
- `-n /pattern/` filters by name.

## Execution

```
spinel test ──fork N workers──▶ each worker: Spinel VM, -r shims/test_worker.rb
                                    │ reads file paths from a pipe, one at a time
                                    │ runs them, streams JSON events back
                                ◀───┘
              aggregates, prints, exits non-zero on failure
```

- `N` = physical cores by default (`-j`). Workers are forked *after* loading `test_helper.rb`/`spec_helper.rb` once in a parent Spinel process, so Rails boot is paid once, not N times. This is the same trick `parallel_tests` and Rails' own parallelization use; Spinel just does it without the gem. `fork` is a phase 3 primitive with CRuby's rule: only from the main Ractor while no other Ractor exists.
- Built (#92), in `shims/test_runner.rb`, which `spinel test` runs on the VM after `shims/setup.rb` and the gem prelude, as `spinel run` runs a program: `lib/` and `test/` go on `$LOAD_PATH`, as Rake's TestTask puts them, and `test/test_helper.rb`, when it exists, is required by its absolute path, so a test file's own `require "test_helper"` or `require_relative` finds it loaded. `N` is the physical cores (`/sys/devices/system/cpu/*/topology` on Linux, `hw.physicalcpu` on macOS), never more than the CPUs the process may run on, and never more workers than files; `-j N` sets it. Each worker has a pipe it reads paths from and a pipe it writes events to; a worker is given its next path only after it reports the last one done, so files go out one at a time. A worker `require`s each file, and after its last one ends as a program ends, so an `at_exit` its helper registered (`minitest/autorun`) runs there; the parent ends with `exit!`, so that `at_exit` does not run again in the parent with no tests loaded.
- RSpec suites run after the Minitest files (#837). Each phase runs in a process of its own forked from the runner, the RSpec one only after the Minitest one has ended, so neither framework's helper or `at_exit` reaches the other's workers: the Minitest phase process requires `test/test_helper.rb` and forks its workers, and the RSpec phase process puts `lib/` and `spec/` on `$LOAD_PATH` as the `rspec` command puts them, requires `rspec/core` and `spec/spec_helper.rb` once, and forks its own. Each phase process ends with `exit!`, after sending the runner what its workers reported ("Output"). A worker requires each spec file it is given, then runs the examples they defined through RSpec's own runner, as `rspec` ends (`RSpec::Core::Runner.disable_autorun!`, then `RSpec::Core::Runner.run([], $stderr, out)`, which reads `.rspec` and `SPEC_OPTS` as usual and loads no file of its own), and exits with its status. Its formatters write to a buffer rather than stdout, as the runner reports the run (#94); the buffer is printed on stderr only when the run fails with no failed example to say why, such as an error in a `before(:suite)` hook. When `rspec/core` cannot be loaded, the spec files are reported on stderr as not run, with the `LoadError`, and the run exits 1.
- Events (#93) are one JSON line each on a worker's pipe back to its phase process: `{"event":"done","file":..,"error":..}` once a file it was given is loaded, `error` the exception loading raised or `null`, and one result per test or example from `shims/test_worker.rb` (below). The phase process splits what it reads into lines and parses each, and skips a line that is not one JSON object; what it does with the results is "Output", below. When `SPINEL_TEST_EVENTS` names a file, each line read is appended to it as it came. // ponytail: the raw stream for tools and tests until `--reporter json` (#95). What went wrong in the run itself, rather than in a test, is printed on stderr, prefixed `spinel test:`.
- A worker that ends before reporting the file it was given done — killed by a signal, or exiting with any status — is reported with that file (`worker 2 (pid 4242) was killed by SIGKILL while running test/b_test.rb`), and a new worker is forked from the parent for the files still waiting, so one crash costs one file. A worker that ends by a signal after its last file, or by a failing status that no failure or error it reported accounts for (`minitest/autorun` exits 1 when a test failed), is reported with the files it ran, and so is a file whose loading raised. Any of these, spec files without `rspec/core`, or finding no test files, exits 1.
- Test files are handed out longest-first using timings recorded from the previous run in `.spinel/test_timings.json`.
- Per-worker databases: if `Rails` is defined, set `ENV["TEST_ENV_NUMBER"]` and `ActiveRecord::TestDatabases.create_and_load_schema` the way Rails' parallelization does. // ponytail: Rails only; other frameworks set `TEST_ENV_NUMBER` themselves.

`shims/test_worker.rb` (#93), which `spinel test` loads before `shims/test_runner.rb` as `-r` loads a library, registers a Minitest reporter and an RSpec formatter that emit one JSON line per event: `{"event":"pass|fail|error|skip","file":..,"line":..,"name":..,"ms":..,"message":..,"backtrace":[..],"rerun":..}`. An `IO` that is not `sync` buffers what it writes, as CRuby's does (#41), so the shim sets `sync = true` on the pipe back to the parent and writes each event in one `write`, under a lock, so a line never straddles two flushes nor mixes with another.

- `file` and `line` are where the test method or the example is defined, `file` relative to the current directory (`test/a_test.rb`, as `spinel test` names the files it hands out); `name` is `Class#test_method` for Minitest and the example's full description for RSpec; `ms` is the run time Minitest or RSpec measured, in milliseconds; `message` is `null` for a pass; `backtrace` is the framework's own filtered backtrace (`Minitest.filter_backtrace`, RSpec's `backtrace_formatter`), each path relative, and `[]` for a pass or a skip; `rerun` is the `file` or `file:line` that `spinel test` runs the test or example again with (#94), relative. That is not always where it is defined: a test from a module, or an example from shared examples, can be defined in a file that is not a test file. Minitest: the file given that defined the test's class, at the test's line when the test is defined in it, else the whole file, and `null` for a class no file given defined. RSpec: the example's `location_rerun_argument`, as RSpec's own summary prints it: the example's location, or that of the nearest group around it in a loaded spec file (the `it_behaves_like` line for a shared example).
- What counts as what is each framework's. Minitest: by a result's first failure, as its `result_code` and its summary count it: a `Minitest::Skip` is `skip`, a `Minitest::UnexpectedError` is `error`, with `message` the wrapped exception's class and message, and any other assertion is `fail`, with the assertion's message. RSpec: by the example's status: `passed` is `pass`, `pending` (a pending example that failed, a skipped one, `xit`) is `skip` with its pending message, and `failed` is `fail`, for an exception as for an expectation, as `rspec` counts both as failures; RSpec has no `error`. A `fail`'s `message` is the exception's message, after its class unless the class's name says `RSpec`, as RSpec's own failure report leaves it out (an expectation not met, a pending example that passed).
- The Minitest reporter is added to the `CompositeReporter` `Minitest.run` builds, by a module prepended to `Minitest.init_plugins`, after every plugin's own, so a plugin that replaces the default reporters (Rails') leaves it, and without adding to `Minitest.extensions`, which on older Minitest 5 releases would stop the gem plugins loading. The same module takes Minitest's `SummaryReporter` and `ProgressReporter` out of the run (#94), whose report the runner's replaces; the reporter's `passed?` is false once a test failed or raised, so `minitest/autorun` still exits 1 without them. // ponytail: a plugin's own printing reporter (Rails' `TestUnitReporter`) still prints; `--reporter` (#95) is where to choose. The RSpec formatter listens on the reporter through `register_listener`, from a `prepend_before(:suite)` hook, after RSpec has set up its formatters from `.rspec` and `SPEC_OPTS`: added before, it would take the place of the default one RSpec adds only when none is configured. // ponytail: `--dry-run` runs no suite hooks, so it emits no results.

## Output

- Default, built (#94): dots while running, then failures with file:line and a trimmed backtrace (gem frames folded), then a summary line. Exit code 1 on any failure.
  - Each phase process prints a character per result as it reads it: `.` a pass, `F` a failure, `E` an error, and a skip as its framework's progress prints one, `S` for Minitest and `*` for RSpec. It keeps every failure and error, counts every result, and keeps each problem from "Execution" (a crash, a file that raised loading, a worker failing with nothing to show for it, spec files without `rspec/core`) with the file to run again when there is one; when it ends, it sends all that to the runner as one JSON document on a pipe of its own. A phase process that ends without sending it is a problem itself.
  - Once both phases have ended, the runner prints each failure and error, the Minitest ones first, each phase's by file and line: `  1) Failure: ReportTest#test_fails [test/report_test.rb:8]`, `Error:` for an error, the `file:line` its test or example is defined at, then the message, then the backtrace (the framework's own filtered one) under `# `, with each run of frames in an installed gem (a path through `gems/NAME-VERSION/` or `bundler/gems/`) folded to one line, `# (3 gem frames)`, and no more than ten of the others, the rest counted. Then the problems, on stderr. Then the summary line, `8 tests, 3 failures, 1 error, 2 skips`, with `, 1 problem` after it when there were any.
  - Failures are re-runnable: under `Re-run each failure:` it prints a `spinel test file:line # name` command for each failure and error, from its event's `rerun` (`spinel test file # name` for a test that runs again with its whole file), and `spinel test file` for each file that crashed or raised loading; the `#` makes the name a comment, so each line runs as pasted into a shell from the project's directory.
  - The exit status is 1 when a test failed or raised or there was any problem, and 0 otherwise, whatever the workers' own exit statuses were.
- `--reporter json` for tools, `--reporter junit` for CI.

## Watch

`--watch` maps changed files to tests to rerun: a changed `test/foo_test.rb` reruns itself; a changed `app/models/user.rb` or `lib/user.rb` reruns `test/**/user_test.rb` and `spec/**/user_spec.rb` by name convention; anything else reruns the last failed set, or everything on Enter. // ponytail: name convention only; a require-graph from the bytecode cache could do better later.

## Not in scope

Coverage (use `simplecov`), mocking, snapshot testing, browser drivers. Spinel gets out of the way.
