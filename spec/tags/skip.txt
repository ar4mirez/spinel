# Examples this engine refuses to run, and why.
#
# Read by `spec/harness`. One `full description<TAB>reason` per line, where the
# description is the one mspec prints: every enclosing `describe`, then the
# `it`, joined by spaces.
#
# This file is not an expected-failure list. An example here is reported
# *skipped* with its reason, never passed and never failed, and every entry
# names a specific engine gap with the slice that closes it. Nothing is added
# here to make a run green — a wrong answer is a bug to fix, and an unfinished
# construct belongs in `Error::Unsupported`, which reports blocked on its own.

empty checks in Regexps shouldn't cause the Regexp parser to get stuck in a loop	/^(()|a|())*?$/ needs Onigmo's capture-restore records: a capture set by a loop iteration survives backtracking out of that iteration, but a capture set outside a loop does not. spinel-regex snapshots captures at every backtrack point, so it restores in both places. Nineteen of this example's twenty assertions already hold; the twentieth needs the restore-record rewrite, not a wider engine. See KNOWN_DIVERGENCES in crates/spinel-regex/tests/oracle.rs.

The defined? keyword when called with a method name having a module as receiver returns nil if the method is private	`defined?(mod.m)` must answer nil for a private method, and Spinel's method table has no notion of public or private yet. #13 named this when it landed `defined?`; the visibility slice is what closes it. Answering "method" here is a wrong answer rather than a missing one, so the example is skipped instead of being left to fail.

Regexp with character classes matches Unicode space characters with [[:blank:]]	`[[:blank:]]` must match U+1680 OGHAM SPACE MARK. spinel-regex's POSIX brackets are the ASCII sets plus the Unicode properties #14 measured, and the blank set is one of the ones still ASCII-only. This became visible rather than blocked when `NilClass#to_a` arrived in #15: the match returns nil and `nil.to_a` is now `[]`. Widening the class belongs with the rest of the dialect work, next to KNOWN_DIVERGENCES in crates/spinel-regex/tests/oracle.rs.

Invoking a method expands the Array elements from the splat before applying block argument operations	`m(*args, &args.pop)` must expand the splat before the block argument is evaluated. Spinel expands splats in the call itself, after every argument including the block is on the stack, so `args.pop` runs first and the splat sees the shortened array. Fixing it means a dynamic argument count at the call site — the count is static on `Insn::Send` today — which is the calling convention's (#11), not the core library's. Became visible when `Array#pop` arrived in #15.

Invoking a method evaluates the splatted arguments before the block if there are other arguments after the splat	The same argument-evaluation order as the entry above, with a positional argument after the splat. One fix closes both.

Kernel#to_enum is defined in Kernel	`to_enum` and `enum_for` answer an `Enumerator`, which needs fibers — phase 2, tracked by #26 and #16. #15 gave `respond_to?` a real answer, which turned this example from blocked into a failure: it asks `Kernel.respond_to?(:to_enum, true)` and Spinel now says false honestly rather than being unable to say anything. Defining a `to_enum` that returns something other than an Enumerator would be a wrong answer.
